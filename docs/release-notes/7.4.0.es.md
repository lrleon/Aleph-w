# Notas de la versión 7.4.0 de Aleph-w

Idioma: [English](7.4.0.md) | Español

Aleph-w 7.4.0 es una versión menor que reemplaza a GSL. Las estructuras
aleatorizadas, los generadores aleatorios y `LFit` ya no llaman a GSL:
sus números aleatorios salen de `Aleph::Gsl_Compatible_Rng`, del header
nuevo `ah-random.H`, que da, para cada semilla, los números de
`gsl_rng_mt19937`, y `LFit` hace por sí mismo los cálculos de GSL. Una
semilla produce los mismos treaps, listas de saltos, grafos, redes,
árboles, cortes, muestras y tablas que con GSL, con menos instrucciones.
La opción nueva de CMake `ALEPH_WITH_GSL`, en ON por omisión hasta
8.0.0, sigue enlazando GSL como antes; en OFF, Aleph ni necesita ni
enlaza GSL, y los programas que enlazan Aleph no reciben de él ninguna
biblioteca GPL. 7.4.0 también corrige los errores que informa `LFit`,
los movimientos de `Treap` y `Treap_Rk` y tres defectos de los
generadores, y depreca `gsl_rng_object()`, `Random_Set::get_rng()`,
`ran_array.h` y `aleph-exceptions.H`.

Es compatible a nivel de código fuente con 7.3.6, salvo por los cambios
de las [Notas para actualizar](#notas-para-actualizar). Como en toda
versión, recompile todo con los headers nuevos
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility), en inglés).

## Notas para actualizar

1. `find_package(Aleph 7 ...)` acepta 7.4.0.
2. Por omisión, `ALEPH_WITH_GSL` está en ON: Aleph sigue enlazando GSL y
   pasándola a los programas que enlazan `Aleph::Aleph`, y los accesores
   deprecados de abajo funcionan como antes. Para compilar sin GSL, que
   entonces no hace falta instalar:

   ```bash
   cmake -S . -B build -DALEPH_WITH_GSL=OFF
   ```

   Aleph define entonces `ALEPH_WITH_GSL=0` para sus consumidores, deja
   fuera los deprecados `gsl_rng_object()` y `get_rng()`, y sus `.deb` y
   `.rpm` no dependen de GSL. Un programa que usa GSL por su cuenta, y
   la recibía de `Aleph::Aleph`, la enlaza entonces él mismo;
   `find_package(Aleph)` deja en `Aleph_WITH_GSL` con qué se compiló el
   paquete:

   ```cmake
   find_package(Aleph 7.4 REQUIRED)
   target_link_libraries(app PRIVATE Aleph::Aleph)
   if(NOT Aleph_WITH_GSL)
     find_package(GSL REQUIRED)
     target_link_libraries(app PRIVATE GSL::gsl)
   endif()
   ```

   OFF pasa a ser lo predeterminado en 8.0.0.
3. De los headers de GSL, Aleph incluye solo `<gsl/gsl_rng.h>`, desde
   `ah-random.H` y mientras `ALEPH_WITH_GSL` valga 1. En 7.3.6 lo
   incluían 13 headers, `random_net.H` incluía además
   `<gsl/gsl_randist.h>`, y `lfit.H` `<gsl/gsl_fit.h>` y
   `<gsl/gsl_statistics_double.h>`: un programa que usa GSL incluye los
   headers que necesita.
4. `gsl_rng_object()` de `Treap`, `Rand_Tree`, `SkipList`, `DynSkipList`
   e `Interval_Tree`, y `get_rng()` de `Random_Set`, están deprecados, y
   llamarlos da una advertencia del compilador. `rng()` da el generador
   de la estructura, cuyos miembros sacan lo que las funciones de GSL
   sacaban de su `gsl_rng` ([Nuevo](#nuevo)):

   ```cpp
   // 7.3.6
   gsl_rng * r = treap.gsl_rng_object();
   unsigned long k = gsl_rng_uniform_int(r, 100);

   // 7.4.0
   unsigned long k = treap.rng().uniform_int(100);
   ```

   Los accesores deprecados pueden lanzar `std::bad_alloc` la primera
   vez, cuando crean su `gsl_rng`, y ya no son `noexcept`. Su `gsl_rng`
   actúa sobre el generador de la estructura, como antes, pero un
   archivo que `gsl_rng_fwrite()` escribe desde él guarda los 2500 bytes
   del estado de un `Gsl_Compatible_Rng`, en el orden de bytes de la
   máquina, y no es el de un `gsl_rng_mt19937`.
5. `LFit` informa otros errores. `mse` es `sumsq / n`, el error
   cuadrático medio, y `sigma` la raíz de `sumsq / (n - 2)`, la
   desviación estándar de los errores que estiman las covarianzas, NaN
   con dos puntos. 7.3.6 tomaba los errores de `x - y` en vez de los
   residuos: para `y = 2x + 1` en `x = 1, ..., 5` daba un `mse` de 4,243
   y una `sigma` de 1,414, donde ahora ambos son 0; con errores de ±0,1
   sobre esa recta, 4,263 y 1,418, donde ahora son 0,0096 y 0,126. `c`,
   `m`, las covarianzas, `sumsq` y `r2` no cambian. `LFit` de arreglos
   vacíos lanza `SizeMismatch`, donde leía fuera de ellos.
6. `Treap`, `Treap_Rk` y `RandTree` no se pueden copiar: una copia
   compilaba, y ambos liberaban el mismo `gsl_rng`. Mover un treap se
   lleva sus nodos y su generador, y deja al movido sin ellos: entonces
   solo puede intercambiarse o destruirse.
7. `rand_gen` (`euclidian-graph-common.H`) es un `Gsl_Compatible_Rng *`,
   y el `r` protegido de `Random_Graph_Base` un
   `Gsl_Compatible_Rng_Owner`: el código que los usaba como un
   `gsl_rng *` llama a sus miembros.
8. `Reservoir_Sampler` lanza `std::bad_alloc`, en vez de
   `std::runtime_error`, cuando no hay memoria para su generador, y
   `std::runtime_error` con el elemento que sigue a 2^32 - 1, donde GSL
   terminaba el programa.
9. `tpl_treapRk.H` ya no incluye `ran_array.h`: un programa que llamaba
   a `ran_start()` o a `ran_arr_next()` a través de él incluye por su
   cuenta `ran_array.h`, que está deprecado ([Deprecado](#deprecado)).
10. Un programa que nombra una clase de `aleph-exceptions.H`, como
    `SizeMismatch`, o usa `DEFINE_ALEPH_EXCEPTION` o `ALEPHTHROW`, avisa
    de su deprecación ([Deprecado](#deprecado)); uno que solo incluye
    `lfit.H`, o atrapa los errores de `LFit` como `std::runtime_error` o
    `std::exception`, no.

## Nuevo

- **`Aleph::Gsl_Compatible_Rng` (`ah-random.H`).** Un Mersenne Twister
  sembrado como GSL siembra `gsl_rng_mt19937` (0 es 4357, y si no cuentan
  los 32 bits bajos), cuyos sorteos siguen los algoritmos de GSL:

  | Miembro | GSL |
  |---|---|
  | `Gsl_Compatible_Rng()`, `seed(s)` | `gsl_rng_alloc(gsl_rng_mt19937)`, `gsl_rng_set(r, s)` |
  | `operator()()`, `get()` | `gsl_rng_get(r)` |
  | `uniform_int(n)` | `gsl_rng_uniform_int(r, n)` |
  | `uniform()`, `uniform_pos()` | `gsl_rng_uniform(r)`, `gsl_rng_uniform_pos(r)` |
  | `flat(a, b)`, `gaussian(sigma)`, `exponential(mu)` | `gsl_ran_flat()`, `gsl_ran_gaussian()`, `gsl_ran_exponential()` |

  Sus números son los de `std::mt19937`, con código en línea, y su
  estado ocupa 2500 bytes. Cumple `std::uniform_random_bit_generator`,
  así que lo aceptan las distribuciones y los algoritmos de la
  biblioteca estándar. `uniform_int(n)` lanza `std::domain_error` con
  `n` = 0 o mayor que 2^32 - 1, donde GSL llama a su manejador de
  errores, que por omisión termina el programa. `flat()` y `gaussian()`
  redondean cada producto, para que una multiplicación-suma fusionada
  del compilador no cambie ningún sorteo: dan los bits de GSL donde GSL
  también los redondea, como en x86-64. `gaussian()` y `exponential()`
  toman el logaritmo de la biblioteca de C, así que pueden diferir de
  GSL en los últimos bits donde GSL toma el de otra, como en Windows; y
  `gaussian()` donde GSL fusiona `x * x + y * y`, como hace la GSL de
  las distribuciones para arm64.
- **`rng()`** da el generador de `Treap`, `Treap_Rk`, `Rand_Tree`,
  `SkipList`, `DynSkipList`, `Random_Set` e `Interval_Tree`. Lo guardan
  en un `Gsl_Compatible_Rng_Owner`, un puntero a memoria de `malloc()`,
  como guardaban su `gsl_rng`, así que conservan su tamaño.
- **`ALEPH_WITH_GSL`**, una opción de CMake ([Notas para
  actualizar](#notas-para-actualizar)); `find_package(Aleph)` define
  `Aleph_WITH_GSL`, y `Aleph::Aleph` tiene la propiedad
  `ALEPH_WITH_GSL`. Las recetas de Conan, vcpkg y Spack toman GSL
  como una opción, encendida por omisión hasta 8.0.0, como
  `ALEPH_WITH_GSL`, y las ruedas de Python se construyen sin ella.

## Deprecado

- `gsl_rng_object()` de `Treap`, `Rand_Tree`, `SkipList`, `DynSkipList`
  e `Interval_Tree`, y `Random_Set::get_rng()`. Use `rng()` en su lugar.
  Existen mientras `ALEPH_WITH_GSL` valga 1, y se eliminan en 8.0.0,
  como prevé el
  [procedimiento de deprecación](../../VERSIONING.md#deprecation-procedure)
  (en inglés).
- `ran_array.h` (`ran_start()`, `ran_arr_next()`, `ran_arr_ptr` y
  `ran_arr_cycle()`), el generador de Knuth, que nada de Aleph usa. Use
  los motores de `<random>` en su lugar. Se elimina en 8.0.0 junto con
  `ran_array.c`: el aviso de Knuth pone su código en el dominio público
  solo mientras no se modifique, y esta copia está modificada.
- `aleph-exceptions.H`: `AlephException`, sus 19 excepciones
  (`SizeMismatch`, `InvalidValue`, `OutOfRange` y las demás),
  `DEFINE_ALEPH_EXCEPTION` y `ALEPHTHROW`. Use en su lugar las macros de
  `ah-errors.H`, que lanzan las excepciones de la biblioteca estándar.
  Se elimina en 8.0.0. Hasta entonces, `LFit` lanza `SizeMismatch`, un
  `std::runtime_error`; desde 8.0.0 lanza `std::invalid_argument`, como
  las macros de `ah-errors.H`: atrapar `std::exception` atrapa ambas.

## Correcciones

- **Un treap movido conservaba la cabecera del otro.** `Treap` y
  `Treap_Rk` guardan su raíz en un enlace de su cabecera, y no tenían
  constructor de movimiento: un treap devuelto desde una de dos
  variables apuntaba a la cabecera de esa variable, que ya no existía, y
  ambos liberaban el mismo `gsl_rng`. Ahora mover se lleva los nodos y
  el generador, y es `noexcept` cuando lo es mover los criterios de
  comparación.
- **Una copia de `RandTree` compilaba,** y ambas liberaban el mismo
  `gsl_rng`.
- **`gen_random_euclidian_graph()` dejaba `rand_gen` asignado cuando el
  grafo aleatorio lanzaba,** apuntando a un `gsl_rng` que nunca
  liberaba.
- **`Reservoir_Sampler::update()` tomaba el elemento que sigue a
  2^32 - 1,** cuyo sorteo entre 2^32 posiciones hacía que GSL terminara
  el programa: lanza `std::runtime_error`, como con los siguientes.
- **`LFit` tomaba sus errores de `x - y`,** y leía fuera de los arreglos
  vacíos ([Notas para actualizar](#notas-para-actualizar)).

[`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md) (en inglés)
registra el código de terceros del repositorio y las bibliotecas que
Aleph enlaza, y `REUSE.toml` declara sus licencias:

  una interfaz de C++ para GMP y MPFR de Jon Wilkening, es

- `ran_array.c` y `ran_array.h` son el `rng.c` de Knuth, bajo su aviso.
- GMP y MPFR son LGPL-3.0-or-later (GMP también GPL-2.0-or-later), y se

  enlaza con el visor de X11 (`ALEPH_BUILD_X11_VIEWER`).

Con `ALEPH_WITH_GSL` en OFF no se enlaza ninguna biblioteca GPL.

## Pruebas

- `ah_random_test` (nueva): los sorteos de `Gsl_Compatible_Rng`, bit a
  bit contra GSL, intercalados, con 13 semillas, y sin GSL por sus
  huellas; sus números contra `std::mt19937`; sus errores, rangos,
  momentos y copias.
- `random_structures_test` (nueva): con 6 semillas, los árboles con sus
  prioridades, los niveles de las listas de saltos, el orden de una cola
  aleatoria y el número siguiente de cada generador son los que las
  estructuras producían con GSL; el `gsl_rng` deprecado; movimientos e
  intercambios.
- `random_generators_test` (nueva): con 6 semillas, lo que producen los
  grafos, digrafos, redes, árboles, cortes de Karger, semillas de un
  filtro de Bloom, muestras de un reservorio, grafos euclidianos y la
  tabla de `jsw_hash()` es lo que producían con GSL.
- `lfit_test`: el ajuste, las covarianzas, `sumsq`, R² y las
  predicciones de 810 conjuntos de datos, bit a bit contra GSL, y los
  errores a partir de los residuos.
- `ran_array_test` (nueva): el número del control de Knuth.
- `aleph_exceptions_test` (nueva): cada excepción de `aleph-exceptions.H`
  y `DEFINE_ALEPH_EXCEPTION`, como antes; y un control que compila
  programas, de que la deprecación avisa donde un programa las usa, y no
  donde incluye `lfit.H` o usa `LFit`.
- El job nuevo `without-gsl` de la CI compila y prueba todo donde GSL no
  está instalada: los 10 casos que comparan con GSL salen `SKIPPED`. En
  Windows, MSVC compila con GSL, cuyas comparaciones pasan allí, y
  `clang-cl` sin ella.

## Rendimiento

Contado con cachegrind, con GCC 14 y Clang 22 a `-O2`, contra 7.3.6,
que toma sus números de GSL. Cada caso es un binario propio, menos las
instrucciones de uno vacío, con `time()` fijo, y ambas versiones dan las
mismas sumas; cada cifra es el cambio en las instrucciones:

| | GCC 14 | Clang 22 |
|---|---|---|
| `Treap<int>`: 20 000 inserciones, búsquedas y eliminaciones | −1,95 % | −1,59 % |
| `Treap_Rk<int>`, lo mismo | −1,47 % | −1,22 % |
| `Rand_Tree<int>`, lo mismo | −12,36 % | −16,97 % |
| `DynSkipList<int>`, lo mismo | −2,91 % | −2,83 % |
| `Random_Set<int>`: 20 000 inserciones y extracciones | −18,33 % | −13,59 % |
| `DynSetTree<int, Treap>`: 20 000 inserciones, búsquedas y eliminaciones | −2,10 % | −1,10 % |
| `Random_Graph`: 2000 nodos, 8000 arcos | −4,58 % | −8,38 % |
| `Random_Graph`: 300 nodos, p = 0,1 | −10,60 % | −13,53 % |
| `Random_Digraph`: 2000 nodos, 8000 arcos | −5,00 % | −9,29 % |
| `Random_Graph::eulerian()`: 500 nodos, 2000 arcos | −3,15 % | −5,22 % |
| `Random_Network_Flow`: 10 rangos de 40 nodos | −10,30 % | −12,29 % |
| `RandTree`: 100 000 nodos | −2,28 % | −2,19 % |
| `Karger_Min_Cut`: 30 iteraciones, 40 nodos | −0,04 % | −0,06 % |

| Un grafo euclidiano: 1000 nodos, 4000 arcos | −5,71 % | −10,31 % |
| `init_jsw()`: 2000 semillas | −44,47 % | −55,06 % |

`LFit`, contado con callgrind dentro de `main`, menos un binario que
solo genera los datos, contra el `LFit` de 7.3.6, que hacía una pasada
más para sus errores, y contra las funciones de GSL llamadas
directamente, que dan las mismas sumas:

| | GCC 14, 7.3.6 | Clang 22, 7.3.6 | GCC 14, GSL | Clang 22, GSL |
|---|---|---|---|---|
| 10^4 ajustes de 10 puntos | −49,21 % | −62,22 % | −21,21 % | −16,83 % |
| 100 ajustes de 1000 puntos | −46,80 % | −64,44 % | −24,43 % | −23,05 % |
| Un ajuste de 10^6 puntos | −45,95 % | −64,15 % | −23,66 % | −23,12 % |
| 10^6 predicciones | −50,00 % | −40,79 % | −53,65 % | −37,47 % |

Y 10^6 sorteos de `Gsl_Compatible_Rng` solo, contra los de GSL, que dan
las mismas sumas:

| | GCC 14 | Clang 22 |
|---|---|---|
| Números (`get()`) | −32,87 % | −46,86 % |
| `uniform_int(1000)` | −49,71 % | −57,44 % |
| `uniform()` | −38,94 % | −51,18 % |
| `gaussian(1)` | −22,19 % | −24,67 % |

Los números salen de código en línea, sin la llamada a través de un
puntero a función que GSL hace para cada uno.
