# Aleph-w 7.0.1 release notes

Language: English | [Español](7.0.1.es.md)

Aleph-w 7.0.1 is a patch release. It fixes defects of 7.0.0, most of them
reported by an audit of that release and the rest found while fixing those:
memory safety and invariants of the flat containers, the tree sets and the
hash tables, wrong results and leaks in shortest paths, integer overflow on
untrusted input, two races in cancellation and the thread pool, and an
installed package that did not give its consumers the C++ standard its
headers need.

It is source compatible with 7.0.0. Several operations now report an error,
or leave the object in another valid state, where 7.0.0 corrupted memory,
lost data or ended the program; [Behavior changes](#behavior-changes) lists
them. As with every release, recompile everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.0.1. A consumer that chooses no
   C++ standard now gets C++20 from `Aleph::Aleph`; one that chooses C++20
   or C++23 keeps it.
2. Three signatures changed, all compatible with the calls that compiled
   with 7.0.0:
   - `is_power_of_2()` and `next_power_of_2()` take a `size_t` instead of an
     `unsigned long`, the same type on Linux and macOS.
   - The free `get_min_path()` of the shortest path algorithms takes the
     distance as a new last parameter, defaulted to `Distance()`.
   - `OLhashTable` and `ODhashTable` also accept a lambda without captures
     where they take a pointer to a hash function.
3. An open addressing table built with `with_resize = false` holds one key
   fewer than in 7.0.0: it is full with `capacity() - 1` keys.

## Behavior changes

### Containers

- **`FlatMap` and `FlatSet`.** If moving their elements cannot throw, the
  insertions, `erase()` and `reserve()` give the strong guarantee. If it can
  and a move throws, the container is left empty, as `std::flat_map` does,
  and the exception propagates. The copy assignment of `FlatMap` is copy and
  swap.
- **`DynSetTree::operator=`** copies the comparator as well and gives the
  strong guarantee. A set that used an arena drops it when it is assigned.

### Hash tables

- **Move, copy and swap.** The move constructor of `OLhashTable` and
  `ODhashTable` takes the buckets of the source in constant time; the source
  is left empty, with capacity 0, and usable. The copy assignment of every
  table is copy and swap: it copies the hash function, the comparator, the
  thresholds and the resize policy, and the target gets the capacity of the
  source. `swap()` exchanges the thresholds and the resize policy too.
  `DynMapHash` has a `swap()` and a move assignment of its own, so that a
  map keeps finding its keys after them.
- **Failed insertions.** `insert()`, `search_or_insert()`,
  `contains_or_insert()` and `operator[]` of the open addressing tables leave
  the table as it was when they throw, and so do `resize()` and `rehash()`.
  The insertions that take an rvalue copy a key whose swap can throw instead
  of swapping it.
- **Full tables.** A table that does not resize itself is full with
  `capacity() - 1` keys. Then `insert()`, `search_or_insert()` and
  `contains_or_insert()` return `nullptr` for a new key, as documented, and
  `operator[]` throws `std::overflow_error`, also in `MapOLhash` and
  `MapODhash`.
- **Shrinking.** `remove_ptr()` shrinks the table only if the keys fit in
  the smaller one under the upper threshold.
- **Chained tables.** `get_lower_alpha()`, `get_upper_alpha()`,
  `set_lower_alpha()` and `set_upper_alpha()` act on the table; in 7.0.0 they
  read uninitialized fields and changed nothing. Those private fields are
  gone, so the chained tables are smaller.
- `stats()` of an open addressing table without buckets returns zeros, not
  NaN.

### Shortest paths

- `Dijkstra_Min_Paths` and `AStar_Min_Path` take every weight from the
  `Distance` given to the constructor, as do `get_min_path()` and
  `get_distance()`.
- If a method throws, the cookies it allocated are freed, `is_painted()` is
  false, and the object and the graph can be used again.
- `is_painted()` is true only if the last computation was a painting that
  ended normally. `copy_painted_min_paths_tree()` returns the weight of the
  painted tree, and the copy is mapped to the graph both ways, as are the
  nodes and arcs of a computed tree.

### Integer overflow

- An integer operation of the compiler toolkit's language whose result does
  not fit in 64 bits is a runtime error in every engine: `RUN013 integer
  overflow` in the HIR interpreter, `BCV023 integer overflow` in the
  bytecode VM, and `integer overflow` in the generated C. The optimizer no
  longer removes dead arithmetic that can stop the program.
- `read_life_105()` and `read_life_106()` throw `std::overflow_error` when a
  coordinate, or the distance between two cells, does not fit in
  `ca_index_t`; their `try_` forms report it as an error. `read_rle()`
  rejects a size beyond `ca_index_t` (`std::overflow_error`) and a run that
  would wrap its size checks (`std::domain_error`), and
  `load_binary_pattern()` a pattern whose size would wrap its fit check.

### Concurrency

- Destroying or assigning a `ConditionVariableRegistration` waits for a
  notification of it in progress.
- A cancellation-aware operation of `BoundedChannel` that blocks with a
  token connected to a source checks the token again every 10 ms.
- If a worker thread cannot be started, the constructor of `ThreadPool`
  stops and joins the workers already started and rethrows; `resize()` does
  the same with its new workers and leaves the pool stopped, as after
  `shutdown()`.

### Utilities

- `next_power_of_2()` throws `std::overflow_error` for a value above the
  largest power of 2 that a `size_t` holds, where it looped forever.
- `to_vector()`, through `ah-stl-utils.H`, reserves the size of the
  container first, as it did through `ah-convert.H`.
- Under C++23, `foldl()` and the folds of `ah-ranges.H` run their own loop
  for an operation that `std::ranges::fold_left` rejects.

## Fixes

- **Containers.** Inserting into a `FlatMap` a key or value that refers to
  an element of the same map used freed memory. An insertion or `erase()`
  that threw could leave `FlatMap` and `FlatSet` with a moved-from entry or
  out of order. `DynSetTree::operator=` lost the comparator, and assigning to
  a set with an arena leaked its nodes. Destroying a degenerate tree of a
  million nodes overflowed the stack; the destruction, copy and height of
  binary trees no longer recurse without bound.
- **Hash tables.** Copying, moving or swapping a table lost its
  configuration, and `DynMapHash` stopped finding its keys after a swap or
  an assignment. `clear()` and `empty()` of the open addressing tables left
  them pointing to freed memory when an allocation failed. An insertion whose
  key copy threw left an entry that nobody inserted, which could crash the
  program later. A table built with `with_resize = false` took a key in
  every bucket, after which `ODhashTable` failed an assertion and
  `operator[]` dereferenced a null pointer. A growth, `rehash()` or
  `resize()` that threw lost keys. `DynMapHashTable::values()` did not
  compile.
- **Shortest paths.** The distance given to the constructor was ignored,
  so a distance with state gave wrong costs and paths. An exception leaked
  the cookies. `copy_painted_min_paths_tree()` always returned 0, a painting
  that no longer existed could still be followed, and the arcs of a computed
  tree were mapped to freed memory.
- **Untrusted input.** The Life readers overflowed while normalizing
  coordinates. The language computed with the overflow of C++ (undefined
  behavior), and `LLONG_MIN / -1` killed the host process with `SIGFPE` on
  x86. The RLE size checks and the fit check of `load_binary_pattern()`
  could wrap.
- **Concurrency.** A cancellation could notify a condition variable that
  had already been destroyed. A pool whose workers could not all start ended
  the program through `std::terminate`. A blocked `BoundedChannel` operation
  could miss its cancellation and sleep on.
- **Headers.** `ah-convert.H` and `ah-stl-utils.H` could not be included in
  the same translation unit. Five installed headers did not compile by
  themselves, and one of them, `ahTypes.H`, did not compile at all.
  `is_power_of_2()` and `next_power_of_2()` cut sizes beyond 32 bits on
  Windows, and `FixedQueue(size_t)` overflowed for capacities above 2^30.
- **Error macros.** An `if` or an `else` whose only statement was an
  `ah_*_if` or `ah_*_unless` macro now has braces at the 29 places of the
  library and the examples that had none. The macros expand to an `if`, so
  an `else` added after one of those places would have belonged to the
  macro; none was there, so nothing changes now. `ah-errors.H` and
  [`docs/ERROR_HANDLING.md`](../ERROR_HANDLING.md) describe the restriction.

## Build, CMake and platforms

- **C++ standard.** `Aleph::Aleph` requires `cxx_std_20` as a usage
  requirement, so a consumer that chooses no standard compiles, whether it
  finds the installed package or adds the sources with `add_subdirectory`.
  `-fno-strict-aliasing`, which `htlist.H` needs, now also reaches consumers
  built with Apple's clang and the sources of the library in every build
  type.
- **Tests and C++23.** The tests are compiled with the standard of the
  build; with `ALEPH_CXX_STANDARD=23`, the library was compiled as C++23 and
  the tests as C++20.
- **New installed header:** `ah-convert-common.H`.
- **Installed-package check.** It compiles by itself every installed header
  but three (see the [correction](#correction-to-the-700-release-notes)),
  and it checks that `Aleph::Aleph` requires C++20. The official consumer
  (`consumer/`) chooses no standard and is built both through
  `find_package` and with `add_subdirectory`.
- **CI.** Several `ctest -E` patterns named test programs instead of the
  GoogleTest names that CTest registers, so they excluded nothing; they are
  gone, and [`docs/ci_sanitizer_policy.md`](../ci_sanitizer_policy.md) lists
  what is really skipped. What the CI runs does not change.
- **Platforms.** CI covers Linux (GCC and Clang, with ASan, UBSan, TSan and
  MSan jobs), macOS (Intel and Apple silicon), Linux arm64 and Windows (MSVC
  and clang-cl), where the tests that need no POSIX-only facility build and
  pass.

## Documentation and packaging

- **Recipes.** The vcpkg port (`ports/aleph-w/`) and the Spack package are
  unverified drafts: their version and the hash of the release tarball are
  placeholders. The Python package `aleph-ca` has a version of its own, a
  pre-release published by hand to TestPyPI. [`VERSIONING.md`](../../VERSIONING.md)
  says so; it claimed that every recipe read `VERSION.txt`.
- [`VERSIONING.md`](../../VERSIONING.md) describes the C ABI of the
  cellular-automata module (`ca-c-api.h`, `libalephca_c`), which exists and
  is still experimental, and lists the releases up to 7.0.1.
  [`SECURITY.md`](../../SECURITY.md) supports 7.x.
- The README examples asked for `find_package(Aleph 4.0 ...)`, which does
  not accept 7.x (so did the usage comment of the installed
  `AlephConfig.cmake`), and for `-DUSE_SANITIZERS=ON`, an option that does
  not exist (the option is `ALEPH_USE_SANITIZERS`). Its figures were
  outdated, it showed a fixed 99.98 % badge, and it said that Boost has no
  order statistics or network flows, and that neither the standard library
  nor Boost has arena allocators.

## Correction to the 7.0.0 release notes

The 7.0.0 notes said that the installed-package check compiles every
installed header by itself. It left eight out, and they did not compile by
themselves. 7.0.1 fixes five of them (`ah-time.H`, `mat_latex.H`,
`hashDry.H`, `single_graph.H` and `ahTypes.H`). The other three are
exceptions documented in the headers: `graph-dry.H`, an internal fragment of
`tpl_graph.H`; `generate_df_tree.H`, legacy code that no longer compiles
with the current graph classes; and `xml_graph.H`, which needs libxml++.
