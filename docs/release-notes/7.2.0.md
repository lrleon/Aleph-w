# Aleph-w 7.2.0 release notes

Language: English | [Español](7.2.0.es.md)

Aleph-w 7.2.0 is a minor release. The hash tables can turn their resizing
on and off with `set_with_resize()`, the open addressing tables that resize
themselves shrink when `remove(key)` takes them under their lower
threshold, and the linear hash table honors `with_resize`.
`generate_df_tree.H` is rewritten so that it draws the depth-first
spanning tree of a graph with the `df` and `low` numbers of its nodes, and
the formatters of `point.H` work with libc++ 17 and 18. It also fixes
several bugs of the hash tables and an overflow of `generate_tree()`.

It is source compatible with 7.1.2, except for converting a `DynLhashTable`
with a comparator of its own to its base class
([Upgrade notes](#upgrade-notes)). As with every release, recompile
everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.2.0.
2. In an open addressing table that resizes itself (`OLhashTable`,
   `ODhashTable` and the sets and maps over them), `remove(key)` can now
   shrink the table and move its keys, as `remove_ptr()` already did; as
   after an insertion, the pointers to its keys are not valid after it. A
   table built with `with_resize = false`, or after
   `set_with_resize(false)`, never moves its keys by itself.
3. `DynLhashTable::insert()` returns `nullptr` when the key is already in
   the table, and leaves the table as it was.
4. `ODhashTable::remove_ptr()` throws `std::invalid_argument` for a pointer
   that does not point into the table, and `std::domain_error` for a key
   already removed, as `OLhashTable::remove_ptr()` did.
5. A linear hash table (`LinearHashTable`, `DynSetLinHash`,
   `DynMapLinHash`) built with `with_resize = false` no longer expands or
   contracts.
6. `DynLhashTable<Key, Record, Cmp>` now derives from
   `LhashTableVtl<Key, Cmp>`, so that it compares with `Cmp`. With a
   comparator other than the default, a conversion to
   `LhashTableVtl<Key>` no longer compiles; use `LhashTableVtl<Key, Cmp>`.

## New

- **`get_with_resize()` and `set_with_resize(bool)`** in the open
  addressing tables, the chained ones and the linear hash table, and so in
  the sets and maps over them. Like `set_lower_alpha()` and
  `set_upper_alpha()`, the change applies from the next insertion or
  removal on: turning the resizing on does not rebuild the table at once.
- **`generate_df_tree.H`** draws, for `ntreepic`, the depth-first spanning
  tree of an undirected graph with the `df` and `low` numbers of its nodes,
  which the computation of cut nodes uses, and its other arcs as dashed
  connections. `write_df_low_tree()` writes it, with the labels of
  `Write_Df_Tree_Low` (`label,df,low`, the default), `Write_Df_Tree_Df` or
  `Write_Df_Tree_Label`, and `build_df_low_tree()` returns it as a
  `Tree_Node<Df_Low_Key>`, with the arcs that are not in it. The numbers
  are those of `Compute_Cut_Nodes`. The graph is a template parameter and
  is not modified. The header was installed, but no program could include
  it: it needed a global graph type and helpers of two example programs
  that are no longer in the repository, and it did not compile with the
  current graph classes.
- **The formatters of `point.H` with libc++ 17 and 18.** The
  `std::formatter` specializations of `Point`, `Segment`, `Triangle`,
  `Rectangle`, `Polar_Point`, `Ellipse`, `RotatedEllipse`, `Point3D`,
  `Segment3D`, `Triangle3D` and `Tetrahedron` were declared only where the
  standard library defines `__cpp_lib_format`, which libc++ defines from
  19 on, although 17 and 18 have `std::format`. They are now declared with
  libc++ 17 and later too, and their `format()` is a template on the
  context, as the `std::formattable` concept asks and libc++ 17 and 18
  need. The text that they write does not change.

## Behavior changes

### Hash tables

- **`remove(key)` shrinks.** In an open addressing table that resizes
  itself, `remove(key)` shrinks the table when its load drops below
  `lower_alpha`, with the rule of `remove_ptr()`: to about half the
  capacity, if the keys fit there under `upper_alpha` and leave an empty
  bucket. The `del()` of an iterator still does not shrink, so that the
  iterator stays valid.
- **The linear hash table honors `with_resize`.** A table built with
  `false` expanded and contracted all the same.
- **Copies of `DynHashTable`** (`DynSetLhash`, `DynSetLinHash`,
  `DynMapHash`, `DynMapLinHash`) keep whether the table resizes itself, as
  they keep the thresholds; they always resized.
- **`DynLhashTable`** compares keys with its `Cmp`, and a copy takes the
  hash function, the comparator, the capacity, the thresholds and the
  resizing of the source. `insert()` refuses a key already in the table.
- **`ODhashTable::remove_ptr()`** checks its argument, as
  `OLhashTable::remove_ptr()` does.

## Fixes

- **`generate_tree()`** wrote past its array for a tree with more than
  `Max_Tree_Node_Depth` (1024) levels: it checked the depth when it entered
  a node, after the parent had written the Dewey number of the child. It
  now checks before writing and throws `std::overflow_error`, as it meant
  to. A tree of 1024 levels is still written.
- **Removals without memory.** When a removal shrank a hash table and the
  smaller table could not be allocated, `remove_ptr()` of the open
  addressing tables threw `std::bad_alloc` after it had removed the key,
  and the removals of the chained tables and of the linear hash table,
  which are `noexcept`, ended the program with `std::terminate()`. Now the
  table keeps its capacity and the key stays removed.
- **`DynLhashTable`** ignored its `Cmp` and compared with
  `Aleph::equal_to<Key>`. Its copy constructor and assignment built the
  copy with the default hash function, capacity and thresholds, always
  resizing, and did not compile for a key type without a default hash
  function; the assignment now copies and then swaps, so that a copy that
  throws leaves the target as it was. `insert()` of a key already in the
  table returned the record of an entry that the table did not hold: the
  record was lost and its memory leaked.
- **`ODhashTable::remove_ptr()`** did not check its argument: in a release
  build, removing the same pointer twice took one more key from the size
  and could make another key unreachable.
- **`busy_slots()` of the linear hash table** drifted from the number of
  non-empty lists: an expansion counted a list that no key went to, a
  contraction into an empty list counted one list less, and `empty()`,
  which `clear()` calls, kept the old count.
- **Chained tables.** A table of 211 lists was rebuilt as it was by every
  removal under `lower_alpha`, since `next_prime()` takes its primes from a
  table where 211 follows 101, so half of 211 is 211 again. And with
  `lower_alpha` over half of `upper_alpha`, a removal could shrink the
  table and grow it back at once. A removal now shrinks the table only to
  a smaller capacity where the keys stay under `upper_alpha`.

## Documentation

- `DynLhashTable::insert()` says that it returns `nullptr` for a key
  already in the table; it said that duplicates were allowed.
- `remove_ptr()` of the open addressing tables documents its exceptions,
  and `generate_tree()` documents that it throws for a tree that is too
  deep.
- [`INSTALL.md`](../../INSTALL.md) no longer lists `generate_df_tree.H` as
  a header that does not compile by itself.
- [`VERSIONING.md`](../../VERSIONING.md) lists 7.2.0.
