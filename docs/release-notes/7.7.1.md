# Aleph-w 7.7.1 release notes

Language: English | [Español](7.7.1.es.md)

Aleph-w 7.7.1 is a patch release of fixes. Most came from a Coverity
Scan of the library with its tests and its examples: each of its 620
reports was checked against the code, with a probe of its own where it
took one, and those that were true and did harm are fixed here, with
some that came up while checking them. A moved-from sketch, a B+ tree
that runs out of memory, a zip function with a one-shot operation, a
short CSV stream and a malformed DIMACS file no longer lose, corrupt or
misread data, and two divisions of polynomials no longer hang.

It is source compatible with 7.7.0, but some functions now throw where
they hung, crashed or returned a wrong result (see upgrade notes 2 to
6). As with every release, recompile everything against the new
headers ([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.7.1.
2. `import_network_from_dimacs()` throws `std::runtime_error`, naming
   the file, the line and the cause, for a malformed file: a line whose
   fields cannot be read, a second problem line, a node or arc line
   before the problem line, a node number outside [1, n], or a
   designation other than `s` or `t`. It crashed before.
3. With floating coefficients, `divmod()` and `pseudo_divmod()` of
   `Gen_Polynomial` throw `std::domain_error` when a coefficient of the
   quotient or of the remainder overflows. Before, they could hang, or
   return an infinite coefficient.
4. A moved-from `HyperLogLog`, `Count_Min_Sketch`, `MinHash` or
   `Reservoir_Sampler` is an empty sketch of the same parameters, so
   building one by move allocates the storage left to the source; a
   move assignment exchanges the two sketches.
5. The zip functions of `ah-zip.H` and `ah-stl-zip.H` call their
   operation as an lvalue, once per tuple: an operation whose only call
   operator takes `&&` no longer compiles with them.
6. The call of `Inversed_Compare` is `noexcept` only if the comparison
   is: `heapsort()`, `faster_heapsort()` and the heapsort to which
   `introsort()` falls back let an exception of the comparator through,
   as `introsort()` documents.
7. `_In_Iterator` no longer compiles on a digraph type, where it only
   saw the loops of the node.

## Fixes

- **zip** (#199): the zip functions called `std::forward<Op>(op)(...)`
  once per tuple, and an operation whose call through an rvalue
  consumes its state lost it after the first call: `zip_all()` returned
  `false` where it had to return `true`. With lambdas and plain function
  objects the code is the same as before.
- **csv** (#199): `csv_skip_bom()` lost the bytes of a stream shorter
  than three bytes ("a" or "ab" were left empty). It peeks now.
- **net** (#199): `import_network_from_dimacs()` checked neither its
  reads nor the node numbers, and a malformed file indexed past its
  vector of nodes (upgrade note 2).
- **polynomial** (#199): with floating coefficients, a coefficient that
  overflowed left a NaN that is never taken as zero, and `divmod()` and
  `pseudo_divmod()` never returned; `pseudo_divmod()` reached it with
  finite inputs (upgrade note 3).
- **link-cut** (#199): `export_to_tree_node()` of a link-cut tree
  dereferenced a null copy when a vertex had been made before its
  parent and that parent was not the root, and it leaked its copies if
  the allocation of its queue failed.
- **streaming** (#200): the four sketches kept their sizes beside the
  arrays that the implicit moves emptied, and a moved-from sketch read
  and wrote storage that it no longer had (upgrade note 4).
- **bplus** (#200): an allocation that failed in the middle of
  `Gen_BPlus_Tree::insert()` lost keys, and, when it split a full root,
  the whole tree, while `size()` kept the count. Failing each allocation
  of one insertion in turn, 42 failures damaged a tree; none does now.
- **fft** (#200): `FFT::zeros()` returned two zeros for
  z^3 + 1e6 z^2 + 1e6 z + 1e-6: its root solver trimmed again the
  balanced polynomial, whose last coefficient the balancing had made
  tiny. The balanced polynomial is evaluated whole now.
- **sort** (#200): a throwing comparator ended the program in the
  heapsorts (upgrade note 6).
- **list** (#194): the copy of a `DynList`, its constructors from a
  range and from an initializer list, and the copy of a `DynSkipList`
  leaked the items already appended when a copy threw or there was no
  memory for a node.
- **graph** (#193): `_In_Iterator` is constrained to the types that are
  not digraphs (upgrade note 7).

## Performance

- **array** (#195): the copy of a `MemArray`, and so of an `Array`, of
  a trivially copyable type uses `memcpy()` from 5 items on, and its
  growth moves the items with `memcpy()`: 87 to 89 % fewer instructions
  to copy an `Array<int>` of 1,024 items, and 9.3 to 11.5 per item,
  from 15.6 and 20.2, to append 1,024 integers to an empty one (GCC 14
  and Clang 18). For 1 to 4 items the copy runs 2 or 3 more.
- **bplus** (#200): an insertion no longer copies the separators of
  every node on the way back from the leaf, which no insertion changes:
  10^6 random `int` keys go in 228 to 279 ms, from 441, 10^6 keys in
  order in 72 ms, from 212, and 2 x 10^5 long strings in 135 to 156 ms,
  from 178.
- **list** (#194): the copy of a `DynList` of 1,000 integers takes
  0.9 % more cycles with GCC 14 and 2.2 % more with Clang 18, the cost of
  freeing the items if a copy throws.

## Tests

- Each fix has tests that fail without it.
- `Tests/bplus_allocation_failure_test.cc` makes each allocation of an
  insertion into a `Gen_BPlus_Tree` fail in turn, on trees of degree 2
  and 16 with `int` and long string keys, and checks the tree after it.
- The heapsorts are tested against McIlroy's adversary, which makes
  `introsort()` fall back to them.
