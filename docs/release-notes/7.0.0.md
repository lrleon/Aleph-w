# Aleph-w 7.0.0 release notes

Language: English | [Español](7.0.0.es.md)

Aleph-w 7.0.0 is a major release. It reworks the array family (`Array`,
`MemArray`, `DynArray`, `ArrayStack`, `ArrayQueue`), makes iteration over
constant containers const-correct, and fixes several memory-safety defects
of 6.x. It is **not source compatible** with 6.x: most of the breaks are
compile errors with a mechanical fix, and a few change behavior silently,
so read [Behavior changes](#behavior-changes) before upgrading.

As with every release, recompile everything against the new headers: no ABI
compatibility is promised between releases ([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade checklist

1. Change `find_package(Aleph 6 ...)` to `find_package(Aleph 7 ...)`. The
   package uses `SameMajorVersion` compatibility, so a request for 6.x does
   not accept 7.0.0.
2. Build and fix the compile errors. Almost all of them come from three
   patterns:
   - `C::Iterator it(c)` where `c` is constant: write
     `auto it = c.get_it();` (it also compiles with 6.x).
   - `Array<T> a(n)`: write `Array<T>::create_reserved(n)`, or see the
     [migration table](../array-storage-contracts.md#array-construction).
   - `DynArray<T> a = n;` or an integer passed where a `DynArray` is
     expected: write `DynArray<T> a(n)`.
3. Review the code the compiler cannot flag (details in
   [Behavior changes](#behavior-changes)). These searches find the usual
   candidates:

   ```bash
   # find_index()/index_of() compared with -1 (now they return size())
   grep -rnE "(find_index|index_of)\(" src/ | grep -E "\-1|npos"
   # ArrayQueue aliases whose result changes after the buffer wraps around
   # (broad: keep the matches on ArrayQueue objects)
   grep -rnE "\.(first|get_first|top|last|get_last|pop|remove_last)\(\)" src/
   # code that expected DynArray to throw invalid_argument on unwritten entries
   grep -rn "invalid_argument" src/
   ```

4. Tree iterators no longer allocate, but they are larger objects (up to
   about 1 KiB); see [their sizes](#tree-iterators-live-on-the-stack).

## Breaking changes

### Constant containers are iterated through `Const_Iterator`

`C::Iterator` can no longer be built from a `const C &`. On a constant
container, `get_it()` returns the new `C::Const_Iterator`, whose
`get_curr()` returns `const T &`.

```cpp
void print(const DynList<int> & l)
{
  for (DynList<int>::Iterator it(l); it.has_curr(); it.next())   // 6.x: compiles; 7.0: error
    std::cout << it.get_curr();

  for (auto it = l.get_it(); it.has_curr(); it.next())           // 6.x and 7.0
    std::cout << it.get_curr();

  for (DynList<int>::Const_Iterator it(l); it.has_curr(); it.next())  // 7.0 only
    std::cout << it.get_curr();

  for (const auto & x : l)                                       // unchanged
    std::cout << x;
}
```

`typename C::Iterator it = c.get_it();` on a constant container fails for
the same reason; use `auto`.

Affected: `DynList`, `DynDlist`, `Array`, `DynArray`, `MemArray`,
`ArrayStack`, `FixedStack`, `ArrayQueue`, `FixedQueue`, `DynListStack`,
`DynListQueue`, `DynSetTree`, `DynMapTree`, the hash tables (`DynSetHash`,
`DynMapHash` and those built on `hashDry.H`), `Random_Set` and `Aleph::Vector`,
plus the containers that derive from them. Aleph itself had to rewrite about
150 such loops, so expect this to be the most frequent error.

### `Array` construction

- `Array<T>(n)` is deleted. In 6.x it meant "empty, with capacity `n`", but
  depending on `T` and the argument type a variadic constructor could win
  and build the one-element array `{n}`. Say what you mean instead:

  | 6.x | 7.0 |
  |---|---|
  | `Array<T> a(n);` then `append()` | `auto a = Array<T>::create_reserved(n);` |
  | `Array<T> a(n); a.putn(n);` | `auto a = Array<T>::create(n);` |
  | `Array<T> a(n);` then `a(i) = ...` | `auto a = Array<T>::create(n);` or `Array<T> a(n, value);` |

  Beware: the new `Array<T> a(n, value)` holds `n` copies of `value`.
- The variadic element constructors are removed: use braces
  (`Array<int> a{1, 2, 3}`) or the new `Array<int>::build(1, 2, 3)` (see
  [New features](#new-features)).
- The range constructor requires an input iterator and a compatible
  sentinel. The iterator-pair constructor that `Special_Ctors` generates
  for the other containers is constrained the same way, so a pair of
  integers never selects it.

### `DynArray`

- `DynArray(size_t)` is `explicit`: `DynArray<int> a = 10;` and passing `10`
  where a `DynArray<int>` is expected no longer compile.
- `operator[]` of a constant `DynArray` returns `const T &` instead of a
  proxy, so writing through a constant array no longer compiles. It also
  throws `std::out_of_range` when `i >= size()` (see
  [Behavior changes](#behavior-changes)).
- `top()`, `get_first()` and `get_last()` of a constant `DynArray` return
  `const T &` (6.x returned `T &`).

### Operations on constant containers pass `const T &`

`traverse()` on a constant container used to hand `T &` to the operation in
most containers. It now passes `const T &`, so an operation that takes
`T &` (and could modify the container) no longer compiles there.

### `ArrayQueue` no longer exposes its buffer

`ArrayQueue` inherits from `MemArray` with protected access: it no longer
converts to `MemArray`, and `access()`, `get_ptr()`, `get_dim()` and
`get_ne()` are not public queue operations. Use `front(i)`, `rear(i)`,
indexing or iteration.

### `noexcept` specifications

`noexcept` was removed where a function can throw, so that the exception
propagates instead of calling `std::terminate`: `Array::get_first()`,
`Array::get_last()`, `ArrayStack::base()`, the `DynArray` geometry helpers,
the constructor, `next_ne()` and `reset_first()` of `BinNodeInfixIterator`,
and `next_ne()` of `BinNodePrefixIterator`. `DynIntervalTree::Iterator` and
`DynListStack::contains()`/`has()` now have conditional specifications. Only
code that asserts these specifications (for example with `static_assert`)
is affected.

## Behavior changes

These compile unchanged but behave differently.

| Change | 6.x | 7.0 |
|---|---|---|
| `find_index()` / `index_of()` of the `ah-dry-mixin.H` mixins (`Aleph::Vector`, `BitArray`, `Tree_Node`, your own classes) when nothing matches | `size_t(-1)` | `size()`, as the classic containers already did |
| `ArrayQueue::first()`, `get_first()`, `top()`, `pop()`, `last()`, `get_last()`, `remove_last()`, `operator[]`, `operator()` after the circular buffer wraps around | physical positions: wrong elements | FIFO order: the oldest is `first()`, the youngest `last()` |
| `c[i]` on a constant `DynArray` with `i >= size()` | returned the slot, or threw `std::invalid_argument` if its block did not exist | throws `std::out_of_range` |
| Reading a `DynArray` entry whose block was never allocated (`a[i]`, `get_first()`, constant `c[i]`) | threw `std::invalid_argument` | returns the default value; on a modifiable array it also allocates the block |
| Iterating or traversing a modifiable `DynArray` with never-written blocks | crashed (null block) | works, and allocates the blocks it visits; use `std::as_const(a)` to read without allocating |
| `Array::operator()` and `MemArray::operator()` with `size() <= i < capacity()` | read the slot | Debug assertion (`i < size()`); use `operator[]` for a checked access |
| `Array::get_first()`, `Array::get_last()`, `ArrayStack::base()` on an empty container | `std::terminate` | throw `std::underflow_error` |
| Moving an `mpz_class`, `mpq_class` or `mpfr_class` of `gmpfrxx.h` | copied: the source kept its value | move construction leaves the source zero (`0`, `0/1`); move assignment exchanges the values |
| An rvalue passed to `nappend()`, `ninsert()`, `append_in_container()`, `insert_in_container()`, `build_container()`, `build_array()` or `build_dynlist()` | copied | moved: an argument passed with `std::move()` is left moved from |
| Return value of `nappend()`, `ninsert()`, `append_in_container()` and `insert_in_container()` | the number of arguments | the number of items the container added: a set leaves out the keys it already holds |
| Return value of `Rand_Tree::insert()` and `Rand_Tree::insert_dup()` | the root of the tree | the node inserted, as documented and as the other trees do |
| `verify()` of the binary search trees, `is_red_black_tree()`, `is_red_black_bst()` and their `_rk` variants | accepted some invalid trees (see [Fixes](#fixes)) | check the invariant at every node, and `verify()` also the order of the keys |

### Tree iterators live on the stack

The iterators of the binary trees (`BinNodeInfixIterator`,
`BinNodePrefixIterator`, and the `Iterator` of the tree classes built on
them, which `DynSetTree` and `DynMapTree` use) no longer allocate while
iterating: the stack of
pending nodes lives inside the iterator, with room for `Node::MaxHeight`
entries, at most 128. `MaxHeight` did not change, but the iterator object
grew:

| Tree | `Node::MaxHeight` | `sizeof` of the iterator, 6.1 | 7.0 |
|---|---|---|---|
| AVL | 40 | 56 B (+ 512 B on the heap) | 368 B |
| Red-black | 128 | 56 B (+ 1 KiB on the heap) | 1072 B |
| Splay, and other trees of the generic `BinNode` | 2048 | 56 B (+ 16 KiB on the heap) | 1072 B |

A tree deeper than that (possible for the unbalanced ones, such as a
splay tree after sorted insertions) moves the pending nodes to the heap;
`next_ne()` may then throw `std::bad_alloc`.

## New features

- `C::build(items...)`: a static member of every container with the
  functional mixin `FunctionalMethods` (lists, arrays, stacks, queues,
  heaps, sets and maps) that builds the container `C{items...}` builds, but
  forwarding the items. An rvalue is moved, so move-only types can be
  stored, and an item may have any type implicitly convertible to the item
  type. The rules of the container apply: a stack ends with the last item
  on top, a queue with the first one in front, and a set or a map keeps the
  first of two equal keys. The derived containers (`DynSetAvlTree`,
  `DynMapRbTree`, `MapOLhash`, `HashSet`, ...) build themselves, and the
  macro `Derived_Build(Name)` gives the same to a class of your own. See
  [`FUNCTIONAL_PROGRAMMING.md`](../../FUNCTIONAL_PROGRAMMING.md#building-a-container-from-its-items-cbuild).
- `nappend()`, `ninsert()`, `append_in_container()`,
  `insert_in_container()`, `build_container()`, `build_array()` and
  `build_dynlist()` forward their items: they also accept move-only types.
- `C::Const_Iterator` for the containers listed above (`ah-iterator.H`).
- `Array<T>::create_reserved(n)` and `Array<T>(n, value)`.
- `DynArray<T>(n, value)` and `DynArray::read(i)`. `read()`, `operator[]`,
  `nth()`, `find_ptr()`, `top()`, `get_first()` and `get_last()` of a
  constant `DynArray` never allocate; an entry that was never written reads
  as the default value.
- `InlineStack<T, N>` (`tpl_arrayStack.H`): a fixed-capacity stack whose
  storage lives inside the object, used by the balanced trees for their
  search paths.
- Move construction, move assignment and `swap()` for `mpz_class`,
  `mpq_class` and `mpfr_class` in `gmpfrxx.h`. Move assignment and `swap()`
  are `noexcept`; move construction of `mpz_class` is `noexcept` with
  GMP 6.2 or later.
- `HashStats::bucket_length(i)`, the number of entries in bucket `i`, used
  by the chain-length statistics of the hash tables.
- AddressSanitizer container annotations for `MemArray`
  (`ALEPH_ANNOTATE_CONTAINERS`, see [Build](#build-cmake-and-platforms)).

## Fixes

- Inserting an element of the container itself (`a.append(a[0])`,
  `q.put(q.front())`, `a.insert(a[1])`) read freed memory when the
  container grew, and a front insertion shifted the element before copying
  it. See [Inserting an element of the same container](../array-storage-contracts.md#inserting-an-element-of-the-same-container).
- `ArrayQueue`: wrap-around aliases (above); copying and reserving a
  wrapped queue preserve FIFO order; `empty()`, `clear()` and
  `empty_and_release()` reset both indices; moved-from queues can be reused.
- Moved-from `MemArray`, `Array` and `ArrayQueue` can be traversed, copied,
  reserved and reused.
- `DynArray`: iterating, traversing or calling `nth()` on never-written
  entries no longer dereferences a null block; creating an iterator no
  longer default-constructs `T`.
- Accessors of empty containers throw instead of calling `std::terminate`
  (above).
- `nth()` of the `ah-dry-mixin.H` mixins checked its bound with `n + 1`,
  which overflowed for `n == SIZE_MAX` and returned a null reference.
- `append_in_container()` and `insert_in_container()` took a leading
  `size_t` lvalue for their internal counter instead of inserting it.
- `FixedQueue`: `front(i)` read past the buffer once the queue had wrapped
  around, and copying a queue that had wrapped around or was full read
  past the buffer or copied nothing.
- `DynSkipList`: the constant `find()` did not compile, and `append()` of
  an rvalue threw for a key already in the set, instead of returning it as
  the overload for lvalues does.
- The search paths of the AVL and red-black trees reserve a slot for the
  head node: a tree as tall as its `Node::MaxHeight` (40 for AVL nodes)
  overflowed its path by one entry.
- `HtdRbTreeRk`: an insertion that ended with a double rotation left the
  subtree counters one short from the new node up to the root, so `size()`,
  `select()` and `position()` were wrong (inserting 1, 3, 2 gave a
  `size()` of 2).
- `Splay_Tree::remove()` lost nodes in a tree with repeated keys
  (`insert_dup()`): removing a key could drop other nodes that held it.
  `Splay_Tree_Rk` was not affected.
- `Rand_Tree::insert()` and `insert_dup()` returned the root of the tree
  instead of the node inserted, so `insert_dup()` of a `DynSetTree` on
  `Rand_Tree` returned the address of another key.
- The functions that validate a tree missed defects. `is_red_black_tree()`
  looked for a red node with a red child only at the root and its two
  children, and compared the black nodes only of the paths that end at a
  leaf; `verify()` of `Avl_Tree`, `Avl_Tree_Rk`, `TdRbTree`, `Treap`,
  `Treap_Rk` and `Rand_Tree` did not check the order of the keys, nor the
  one of `Treap_Rk` its counters; `DynSetTree::verify()` checked the order
  with the default comparator, and was false for a valid set with another
  one; `HtdRbTree::verifyRedBlack()` did not compile. Now each one checks
  its invariant at every node, in linear time, and `verifyRedBlack()`
  returns a `bool`. The new `Tests/search_trees_battery_test.cc` runs the
  14 tree types against a `std::multiset` with `verify()` after every
  operation: every insertion order of up to 8 keys, every removal order of
  up to 7, long random sequences and the adverse orders.
- Documentation: `rbNode.H` and `tpl_rb_tree.H` listed "the root is black"
  among the properties of the red-black trees. None of the six
  implementations forces it (the only node of a tree is red), and they do
  not need to: a red root has black children, so the height is still at
  most 2 log2(n + 1). The documentation now says so, and `verify()`
  accepts a red root as before.
- Windows: `ah_cpp_compat_test` conflicted with the global `::unexpected()`
  of the UCRT; MSVC fell back to `Pair(key, Data())` in `DynMapHash` search
  and required a default-constructible `Data`; `point_utils_header_test`
  needed a `libgmpxx` operator that does not link on Windows.

## Build, CMake and platforms

- **Sanitizers.** With `ALEPH_USE_SANITIZERS=ON`, `MemArray` poisons the
  reserved slots beyond `size()` (option `ALEPH_ANNOTATE_CONTAINERS`, ON by
  default). The macro changes the layout of `MemArray` under ASan, so the
  `Aleph` target now publishes it, together with the sanitizer options, to
  its consumers and to the installed CMake package. See
  [Logical bounds and AddressSanitizer](../array-storage-contracts.md#logical-bounds-and-addresssanitizer).
- **Clang with libc++ outside macOS.** `gmpfrxx_test` is skipped, as
  `k2tree_test` already was: the system `libgmpxx` is built with libstdc++.
  See [`docs/ci_sanitizer_policy.md`](../ci_sanitizer_policy.md).
- **Platforms.** Linux (GCC and Clang, with ASan, UBSan, TSan and MSan
  jobs), macOS (Intel and Apple silicon) and Linux arm64 are covered by
  CI. On Windows (MSVC and clang-cl), the CI build had stopped at an early
  error since 5.2.0, which hid later failures; this release fixes the
  causes found so far.

## Note on the deprecation policy

[`VERSIONING.md`](../../VERSIONING.md#deprecation-procedure) asks for a
deprecation period before a public API is removed. `Array<T>(n)`, the
variadic `Array` constructors and the construction of `C::Iterator` from a
constant container were removed in this major release without that period.
The compile error points at each affected line, and the migration is
mechanical.
