# Aleph-w 7.5.0 release notes

Language: English | [Español](7.5.0.es.md)

Aleph-w 7.5.0 is a minor release that fixes what a review of 7.4.0
found in `al-domain.H`, `al-vector.H` and `al-matrix.H`, `K2Tree`,
`IO_Graph`, the thread pools `WorkersSet` and `QueueTheadsPool`, the
index of the k shortest paths of Eppstein, and Johnson. A vector no
longer reads freed memory through `v[k]`, nor a vector or a matrix a
domain that is gone; their keys and numbers are constrained by
concepts; a point inserted outside the region of a `K2Tree` is found; a
corrupted stream no longer makes a load of `IO_Graph` read outside its
table; a node too far from the target no longer makes every query of
Eppstein throw; and a potential below `lowest()` no longer loses the
queries of Johnson. 7.5.0 also deprecates `VoronoiDiagramFortune`, which
now computes as `VoronoiDiagram`, and the pools: they go in 8.0.0.

It is source compatible with 7.4.0, but for the changes listed in the
[Upgrade notes](#upgrade-notes). As with every release, recompile
everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.5.0.
2. `AlDomain`, `Vector` and `Matrix` ask for keys and numbers that
   satisfy the new concepts ([New](#new)), and each member for the
   operations that it uses: a type that cannot be a key or a number
   fails where the class is named, instead of deep inside a member. No
   use that worked stops compiling; `int`, `char`, `std::string`,
   `float`, `double` and `mpq_class` are keys or numbers, as they were.
3. `Vector<K, N> v(10)` and `Matrix<R, C, N> m(2, 3)` no longer compile:
   they turned the numbers into empty temporary domains, to which the
   vector or the matrix then pointed. Give a domain, which a vector or a
   matrix copies when it is a temporary:

   ```cpp
   // 7.4.0: compiled, over a domain that no longer existed
   Vector<int, double> v(10);

   // 7.5.0
   Vector<int, double> v(IntRange(10));
   ```

4. `Vector::to_list()` gives the values in the order of the keys, as the
   constructor from a list takes them; 7.4.0 sorted the values.
   `Matrix::to_str()` puts the labels in the order of the keys; 7.4.0
   sorted them as strings, "10" before "2".
5. `IntRange` throws `std::domain_error` for a step of 0, and for a size
   that does not fit in an `int`, as `IntRange(-1)`, where it looped
   forever. The constructor of `Matrix` from lists of lists,
   `create_by_rows()` and `create_by_columns()` throw `std::range_error`
   for rows of the wrong length or a wrong number of vectors, and
   `std::domain_error` for vectors over other domains, as the
   constructor from braces did.
6. A point that `K2Tree::insert()` takes outside the region of the tree
   extends the region, and the rectangles of the nodes are computed
   again, in O(n) for that insertion; `build()` extends it to the points
   outside `[pmin, pmax]` too. In 7.4.0 `range()` left such points out,
   `nearest()` could give another point, farther, and `insert()` threw
   `std::range_error` when a node outside the region got a child.
7. `IO_Graph::load()` and `load_in_text_mode()` throw
   `std::runtime_error` for an arc whose index is not that of a node of
   the stream, and a failed load removes what it added: the graph is as
   it was. A load adds the nodes and the arcs of the stream to the graph,
   as it did; the documentation of 7.4.0 said that it cleared the graph.
   The default functors of the binary mode, which write the bytes of the
   infos, do not compile for an info that is not trivially copyable, as
   `std::string`: give functors of your own then. The binary format
   depends on the sizes and the byte order of the machine.
8. `eppstein_k_shortest_paths()` throws `std::overflow_error` only for a
   walk that is asked and whose cost does not fit. In 7.4.0 a node whose
   distance to the target did not fit made every query to that target
   throw, though no walk that was asked went through it.
9. With weights of a signed integer type, the constructor of `Johnson`
   no longer throws `std::overflow_error` when a potential is below
   `lowest()`. Then a query throws it only when its distance does not
   fit, now also below `lowest()`, and `get_potential()` throws it for a
   potential below `lowest()`. A negative cycle whose sums go below
   `lowest()` throws `std::domain_error`, as the other negative cycles
   do, where 7.4.0 threw `std::overflow_error`.
10. The deprecated pools ([Deprecated](#deprecated)) change too.
    `WorkersSet::schedule_call()` throws `std::overflow_error` on a full
    queue, which only an assert checked, and
    `wait_until_all_workers_finished_or_job_is_done()` returns when the
    pool is shut down. The destructor of `QueueTheadsPool` shuts the
    pool down, where it threw, which ended the program, if `shutdown()`
    had not been called; `create_thread()` throws `std::domain_error`
    for an event of another thread before it starts a thread; and
    `shutdown()` ends the threads of a suspended pool too, waits for a
    shutdown that another call started, and, called from an event of
    the pool, starts the shutdown and returns.

## New

- **The concepts of the keys and the numbers of `al-*.H`.**
  `al-domain.H` gives `AlDomainKey`, what every domain does with a key
  (the default constructor, the copy and `==`), `AlOrderedDomainKey`,
  which adds `<`, and `AlStreamable`; `al-vector.H` gives `AlNumber`,
  what every vector and matrix does with a number (0 and the epsilon
  are numbers, and a number is zero by its absolute value),
  `AlAdditiveNumber`, `AlMultiplicativeNumber` and `AlDivisibleNumber`.
  A key without `<`, or a number without `/`, makes a vector whose
  entries are set and read, without the members that need them.
- **`v[k]` of a constant `Vector`** gives the value; it did not compile.

## Deprecated

- `VoronoiDiagramFortune`. Use `VoronoiDiagram` instead, which it calls
  now, and which gives the same diagram. It goes in 8.0.0, as the
  [deprecation procedure](../../VERSIONING.md#deprecation-procedure)
  provides.
- `WorkersSet` (`worker_pool.H`), `QueueTheadsPool` and the global
  `ConsumerQueueEvent` (`q-consumer-threads.H`), which nothing of Aleph
  uses. Use `ThreadPool` (`thread_pool.H`) instead. They go in 8.0.0,
  and until then they are fixed ([Fixes](#fixes)).

## Fixes

- **The proxy of `v[k]` read and wrote freed memory.** It kept pointers
  to the key, a temporary for `v[2]`, and to the entry, which the growth
  of the table moves; it keeps the key now, and finds the entry each
  time. `v[i] = v[j]` did nothing when `v[j]` was 0, `v[i] = x` did not
  compile for a variable `x`, and `v[i] = v[j] = x` left `v[i]` at 0.
- **A vector or a matrix over a temporary domain pointed to it after it
  was gone,** and so did the transpose, the rows, the columns, the
  products and `outer_product()` of a matrix that owns its domains: they
  keep a copy of a temporary domain, and share those of the matrix, now.
- **`AlDomain::keys()` kept the keys of its first call,** after the
  insertions and the removals, and `al-domain.H` did not compile on its
  own.
- **`IntRange` looped forever** with a step of 0 and with a size beyond
  an `int` ([Upgrade notes](#upgrade-notes)), and its loop took a
  `long`, which overflows near `INT_MAX` where `long` has 32 bits, as on
  Windows.
- **`transpose()` and the products of matrices did not compile** where
  the rows and the columns have different types, where the second matrix
  has other columns, or where the numbers are not `double`.
- **The scalar product of vectors of `mpq_class` read a freed temporary**
  of GMP.
- **`K2Tree` lost the points inserted outside its region**
  ([Upgrade notes](#upgrade-notes)), and `KDTreePointSearch`, over a
  `K2Tree`, threw `std::range_error` from `debug_snapshot()` for such
  points: it splits from its bounds extended to them now.
- **`VoronoiDiagramFortune` ran Bowyer-Watson**, quadratic in Aleph, then
  a sweep of Fortune in `double` and a check of it, to give the diagram
  of `VoronoiDiagram`: it calls `VoronoiDiagram` now
  ([Performance](#performance)).
- **`WorkersSet`**: a worker wrote `job_done` without the lock, while
  the others read it with it, and a false result could reset a true one;
  the items after the job was done, and those still queued at the
  destruction, were not freed; the wait had no predicate, so that it
  waited forever when the items were done before it;
  `prepare_num_workers()` did not wake the workers; and `is_jobs_done()`
  did not compile.
- **`QueueTheadsPool`**: a thread started before its event was checked,
  and the pool did not count it; `shutdown()` waited forever for a
  suspended pool, and when an event of the pool called it; and the
  global `ConsumerQueueEvent` declared `run()` pure but not virtual, so
  that it did not compile.
- **`IO_Graph` read an entry of its table that holds no node** for an
  arc index beyond the nodes of the stream, or negative; it reserved
  memory for the count of nodes of the stream, which a corrupted one
  makes huge, and now for 2^20 nodes at most; and it left in the graph
  what a failed load had read ([Upgrade notes](#upgrade-notes)).
- **The index of Eppstein threw `std::overflow_error`** for a node whose
  distance to the target did not fit ([Upgrade notes](#upgrade-notes)):
  it leaves out such a node now.
- **`Johnson` lost every query** when a potential was below `lowest()`
  ([Upgrade notes](#upgrade-notes)): it computes the potentials again in
  an integer of 128 bits, of two words of 64, and keeps there the new
  weights and the sums of Dijkstra.

## Tests

- `al_concepts_test` (new): which keys and numbers each concept takes,
  that each member is there or not as the types have what it needs, and
  computations with keys without `<`, numbers without `/` and exact
  rationals.
- `al-domain`, `test_al_vector` and `al_matrix_test`: each defect of
  `al-*.H`; against the headers of 7.4.0 they fail, do not compile, or
  AddressSanitizer reports them, but the range of `IntRange` up to
  `INT_MAX`, which fails only where `long` has 32 bits.
- `k2tree_test`: `range()` and `nearest()` with points outside the
  region, against brute force among 400 points of a box five times the
  region, `build()`, and a tree of the default constructor. The tests of
  geometry check `debug_snapshot()` of `KDTreePointSearch` with points
  outside its bounds, and the vertices of `VoronoiDiagramFortune`
  against those of `VoronoiDiagram` and of `VoronoiDiagramFromDelaunay`,
  which triangulates with Bowyer-Watson.
- `worker_pool_test` and `q_consumer_threads_test` (new): each defect of
  the pools. They pass with ThreadSanitizer, and with AddressSanitizer
  and LeakSanitizer; against the headers of 7.4.0 they hang, end the
  program or do not compile, but for the consumption of the items, which
  worked.
- `io_graph_test`: the indices beyond and below the nodes, in both
  modes, the failed loads, a count of nodes that is the greatest
  `size_t`, and a load of 2^20 + 2 nodes. A case of
  `graph_contract_compile_check.cmake` checks that the binary mode does
  not compile with `std::string` infos, and that the text mode does.
- `k_shortest_paths_test` and `johnson_test`: a node beyond `max()`
  apart from the query, on a digraph and on a graph; potentials below
  `lowest()` with `short`, `int` and `long long`; and a negative cycle
  of large weights. The harness of the paths takes the weights
  `lowest()`, -1, 1 and `max()` on every digraph of up to 3 nodes and 3
  arcs, against its oracle.
- On Windows, MSVC and `clang-cl` pass every test, the range of
  `IntRange` up to `INT_MAX` among them.

## Performance

Counted with cachegrind, with GCC 14 and Clang 22 at `-O2 -DNDEBUG`, one
program per case, each change against the code before it; each figure is
the change in the instructions:

| | GCC 14 | Clang 22 |
|---|---|---|
| `Vector::to_list()` and `to_str()` | −34.20 % | −34.01 % |
| `Matrix::to_str()`, 40 × 40 | −3.28 % | −3.23 % |
| Writes and reads through `v[i]` | +0.95 % | −3.29 % |
| Assignments through `v[i]` to entries that are there | +8.83 % | −9.67 % |
| Rows, columns, transpose and products, 120 × 120 | +0.16 % | −0.36 % |
| `K2Tree::insert()` inside the region | +1.74 % | +1.58 % |
| `Johnson`: the constructor | −0.11 % | −0.12 % |
| `Johnson`: the queries from the tree that is kept | −3.37 % | −0.85 % |
| `Johnson::get_potential()` | +1.58 % | +1.36 % |

GCC inlines the search of the table into the assignments through `v[i]`
of the program before, which has one caller, and calls it in the new
one: with all the cases in one program, the new code runs 4.7 % to 9.4 %
fewer instructions. The products of matrices run 0.1 % more with GCC,
which no longer inlines `product_by_scalar()` into `operator*()`.
`get_potential()` takes two more instructions, to tell a potential below
`lowest()`. A load of `IO_Graph` runs 0.2 % to 0.7 % more, for the check
of the indices; `range()` and `nearest()` of `K2Tree`, the queries of
Eppstein and of Yen and the paintings of Dijkstra run as many as before,
within 0.04 %.

`VoronoiDiagramFortune`, timed: 0.12 s instead of 2.2 s for 1 000 sites,
and 0.49 s instead of 19.8 s for 3 000.

## Documentation

- `io_graph.H` documents that a load adds to the graph, what it checks
  and undoes, and that the binary format depends on the machine.
- `worker_pool.H`, `q-consumer-threads.H` and
  [`THREADS_AND_CONCURRENCY.md`](../../THREADS_AND_CONCURRENCY.md) say
  that the pools are deprecated, and give `ThreadPool` instead; the
  example of `WorkersSet` allocates its items with `malloc()`, which the
  pool frees with `free()`.
- `Johnson.H` and `K_Shortest_Paths.H` document which distances and
  walks throw for not fitting.
- [`VERSIONING.md`](../../VERSIONING.md) lists 7.5.0.
