# Aleph-w 7.1.1 release notes

Language: English | [Español](7.1.1.es.md)

Aleph-w 7.1.1 is a patch release that fixes the Linux packages. The `.deb`
of 7.1.0 did not install on Ubuntu 26.04 or Debian 13, and where it did, a
consumer of `Aleph::Aleph` could not link with only what it depended on.
Neither the `.deb` nor the `.rpm` shipped `libalephca_c`, the library that
their `ca-c-api.h` declares. Now the `.deb` is tested installed on Ubuntu
22.04, 24.04 and 26.04 and Debian 12 and 13 before it is attached to the
release. `ah-chronos-utils.H` also compiles with GCC 11 and 12.

It is source compatible with 7.1.0. As with every release, recompile
everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.1.1.
2. Install the `.deb` with apt, so that it brings what the package depends
   on: `sudo apt install ./aleph-w-7.1.1-Linux.deb`. It now depends on the
   development packages of GMP, MPFR, GSL and X11 (`libgmp-dev`,
   `libmpfr-dev`, `libgsl-dev` and `libx11-dev`), which a consumer of
   `Aleph::Aleph` links.
3. A C program builds against the installed C ABI library with
   `-I/usr/include/aleph -lalephca_c`. The CMake package does not export a
   target for it.
4. `Aleph::duration_to_string()` (`ah-chronos-utils.H`) is declared only
   where the standard library has `std::format`: where it defines
   `__cpp_lib_format`, as libstdc++ does since GCC 13, and with libc++ 17
   and 18, which have `std::format` without defining it. With GCC 11 and
   12, or libc++ 14 to 16, the header now compiles without it; with 7.1.0
   it did not compile there.

## Fixes

- **What the `.deb` depends on.** It depended on run-time libraries of
  given versions (`libgsl27 | libgsl25 | libgsl23`, among others), so it
  did not install where GSL is `libgsl28`, as in Ubuntu 26.04 and Debian 13.
  Where it installed, a consumer of `Aleph::Aleph` failed to link on a
  system without the development packages:
  `No rule to make target '/usr/lib/x86_64-linux-gnu/libX11.so'`.
- **The C ABI library.** The `.deb` and the `.rpm` shipped `ca-c-api.h`
  without `libalephca_c`, as in 7.0.0 and 7.0.1: the packages were built
  without the library, and its install rule is optional. They now ship
  `libalephca_c.so.1.0.0` and its links, and the workflow that builds them
  fails if a package lacks it.
- **`ah-chronos-utils.H`** included `<format>`, which libstdc++ has since
  GCC 13. With the GCC of Ubuntu 22.04 and Debian 12, it was the only
  header that the installed-package check could not compile.

## Packaging

- **Built on Ubuntu 22.04**, the oldest distribution supported, with its
  GCC 11, instead of on Ubuntu 24.04 with GCC 13. What is built against an
  older glibc and libstdc++ runs with newer ones, and the static library
  built by GCC 11 links with GCC 12 to 15.
- **`libalephca_c` depends only on what it uses.** It uses no symbol of
  GMP, MPFR, GSL or X11, but it was linked with them, because `Aleph`
  brings them. On Linux it is now linked with `--as-needed`, so at run time
  it needs only `libstdc++`, `libgcc_s` and `libc`, also when it is built
  from the sources. The `.deb` adds
  `libc6 (>= 2.14), libgcc-s1 (>= 3.0), libstdc++6 (>= 11)` to its
  dependencies, and runs `ldconfig` after it installs or removes the
  library.
- **Tested before it is attached.** The release workflow installs the
  `.deb` with apt on clean Ubuntu 22.04, 24.04 and 26.04 and Debian 12 and
  13, and builds against it the official consumer, a C program and the
  installed-package check, which compiles every installed header with the
  GCC of each distribution. The packages are attached to the release only
  if all of them pass. A `v*` tag pushed by hand runs the same checks.
- **The `.rpm`** ships the same files as the `.deb`. It still requires the
  run-time packages and installs the libraries under
  `/usr/lib/x86_64-linux-gnu`, and it is not tested on an RPM distribution.
