# Aleph-w 7.7.3 release notes

Language: English | [Español](7.7.3.es.md)

Aleph-w 7.7.3 is a patch release. It wins back the speed that 7.7.2 took
from the searches of a `DynMapTree` by keys that are not scalars, as
`std::string`, compiled with Clang, and it closes the five reports of
the Coverity Scan of the library that were marked as needing a model.
Three were real defects, of `BitArray::load()` and of the nodes of the
lists and of the trees built by default; the code now rules out the
other two by itself, without a modeling file.

It is source compatible with 7.7.2, but `BitArray::load()` throws for a
damaged header that it accepted (see upgrade note 2). As with every
release, recompile everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.7.3.
2. `BitArray::load()` throws `std::runtime_error`, and leaves the array
   as it was, for a header whose number of bits wrapped its check
   around, as 0 bytes and 2^64 − 1 bits, which it accepted. A header of
   more bytes than a `DynArray` holds (`DynArray::Max_Dim_Allowed`,
   2^38) throws `std::runtime_error` before anything is reserved: it
   reserved memory for every byte first, and then threw
   `std::runtime_error` or `std::bad_alloc`. A header of more bytes
   than the input has still throws, now with the memory of the bytes
   read.
3. The item of a `Dnode` or of a `Tree_Node` built by default is `T()`:
   zero for an arithmetic type or a pointer, where it was indeterminate.

## Fixes

- **bitarray** (#207): `load()` checked that the header agreed with
  `(num_bits + 7) / 8`, a sum that wraps near the maximum of `size_t`:
  a header of 0 bytes and 2^64 − 1 bits passed, and `save()` then
  walked 2^61 bytes. And it made room for every byte of the header
  before it read the first one: a file of 33 bytes whose header
  declares 2^44 bytes made the resident memory grow from 3.2 to 131 MB,
  and one that declares 2^50 bytes asked for 8 GB (upgrade note 2).
  Coverity reported the loop on the bytes as unbounded (CID 173446).
- **list, tree** (#207): `Dnode` and `Tree_Node` default-initialized
  their item. The header of a list never reads it, but a `RandTree`
  gave its caller a root with that key: with MemorySanitizer and
  valgrind, reading the key of the root of a `RandTree<int>` was a use
  of an uninitialized value (CIDs 173383 and 173397, upgrade note 3).
- **graph** (#207): `List_Graph::insert_arc()` releases the arc nodes
  from their guards before it links them, so that no guard owns a
  linked node. Coverity took the old order, which linked a node that
  its guard still owned, for an escape of the pointer (CIDs 173255 and
  173560). Nothing between the link and the release could throw, so it
  was not a defect, and the behavior and the instructions per arc are
  the same.

## Performance

- **maps** (#206): 7.7.2 made `DynMapTree` search by the key, without
  building a pair, with one comparison per level for the keys that are
  not scalars. Clang compiles that descent without a branch, so that
  each level waits for the comparison of the one above: against 7.7.1,
  in an AVL tree of 100,000 pairs, the hits with `std::string` keys of
  16 and 60 characters took up to 17 % more cycles with Clang 18, and
  the misses 19 % more. Every key now descends with two comparisons per
  level, as the scalar keys did. Against 7.7.1, with GCC 14 and Clang
  18, the hits with keys of 16 and 60 characters take 5 to 30 % fewer
  cycles, the `int` keys run the same code, and the keys of up to 15
  characters, kept inside the string, take up to 4 % more cycles with
  GCC and 2 % more with Clang.
- **list, tree** (#207): building a `Dnode` or a `Tree_Node` by default
  stores the zero of its item: one instruction more, 0.55 to 0.58 % on
  creating and destroying an empty `DynDlist<int>` or a lone
  `Tree_Node<int>`, the worst case.
- **bitarray** (#207): `load()` runs two instructions more per byte, of
  some 540 that reading each byte takes (+0.37 %).

## Tests

- Each fix has tests that fail without it:
  `BitArrayPersistence.load_rejects_a_header_whose_bits_wrap`,
  `.load_rejects_a_header_with_too_many_bytes` and
  `.load_of_a_truncated_payload_throws`,
  `Dnode.default_item_is_value_initialized`,
  `Tree_Node.default_key_is_value_initialized` and
  `RandomTreeTest.EveryKeyIsValueInitialized`.
- `DynMapTreeSearchByKey.FindsEveryStringKeyAndNoOther` searches eight
  kinds of tree, with keys of 7, 16 and 60 characters with and without
  a common prefix, for every key and for keys before, after and between
  them.
