# Aleph-w 7.3.0 release notes

Language: English | [Español](7.3.0.es.md)

Aleph-w 7.3.0 is a minor release. Floyd-Warshall takes a distance
instance, as the other graph algorithms already did, and so do the filter
of a painted minimum spanning tree and the totalizer of the shortest path
classes. The conditional error macros now take no `else`: one written
after them belonged to their own `if`. And the operator of the filter and
of the totalizer is no longer `noexcept`, so what the distance throws
reaches the caller.

It is source compatible with 7.2.2, with changes of behavior in the error
macros ([Upgrade notes](#upgrade-notes)). As with every release, recompile
everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.3.0.
2. The conditional macros of `ah-errors.H` (`ah_*_if`, `ah_*_unless`,
   their `_constexpr` forms and the warnings), of `parse_utils.H`
   (`ah_parse_error_if` and `ah_parse_error_unless`) and of `ah-trace.H`
   are loops whose statement runs at most once, instead of `if` statements
   without braces:
   - An `else` written after one of them belongs to the `if` around it,
     as the code says. It belonged to the `if` of the macro, so code that
     has one now runs its `else` when the `if` around it does not hold,
     instead of when the condition of the macro does not.
   - An `else` right after one of them, with no `if` around it, no longer
     compiles.
   - The `_constexpr` forms compile their message even where their
     condition is false, so the message must compile for every
     instantiation; an `if constexpr` used to discard it.
   - A message whose last `<<` does not give back a stream no longer
     compiles; it threw nothing.
3. `operator()` of `Painted_Min_Spanning_Tree` and of
   `Shortest_Path_Base::Total` is no longer `noexcept`: what the distance
   throws reaches the caller.

## New

- **Floyd-Warshall takes a distance.** `Floyd_All_Shortest_Paths` gets a
  constructor `(g, distance, sa = SA())`; the other two pass it a
  `Distance()`. The solver keeps a copy, which the matrices and
  `get_min_path()` use, so a distance may have state, or no default
  constructor, and its call operator need not be `const`. Kruskal, Prim,
  Dijkstra, A*, Bellman-Ford and Johnson already took one.
- **The filter of a painted minimum spanning tree and the totalizer** of
  the shortest path classes, `Painted_Min_Spanning_Tree` and
  `Shortest_Path_Base::Total`, get an `explicit` constructor that takes
  the distance, and keep a copy.

## Behavior changes

### Error macros

- **An `else` after a conditional macro.** The macros were `if`
  statements without braces, so an `else` written after one of them
  belonged to the `if` of the macro:

  ```cpp
  if (checked)
    ah_domain_error_if(x < 0) << "x is negative";
  else       // ran when checked and x >= 0, never when not checked
    use(x);
  ```

  They are now a `while` for those that throw, whose statement always
  throws, a `for` of one iteration for those that write, and
  `do { ... } while (false)` for the `_constexpr` forms of
  `ah_bad_alloc`. A loop takes no `else`, so the `else` belongs to the
  `if` around the macro. The condition is evaluated once, and nothing
  changes at the call sites. In six hot paths that go through them, GCC
  14 and Clang 22 with `-O2` execute the same number of instructions as
  with the old macros.
- **The `_constexpr` forms** are `while (std::bool_constant<(C)>::value)`:
  they still require a constant condition, but compile their message
  where it is false too. Keeping it discarded takes an `if constexpr` with
  an `else`, which makes GCC and Clang warn with `-Wdangling-else` in
  `if (a) macro;`.

## Fixes

### Graph algorithms

- **Distances that throw.** `operator()` of `Painted_Min_Spanning_Tree`
  and of `Shortest_Path_Base::Total` was `noexcept`, so a distance that
  threw ended the program.

### Error macros

- **An `else` after a conditional macro** belonged to the `if` of the
  macro ([Behavior changes](#error-macros)).

## Known issue

- **Floyd-Warshall and negative cycles.** Since 7.2.1, the constructor of
  `Floyd_All_Shortest_Paths` may throw `std::overflow_error` instead of
  reporting a negative cycle, in graphs of a few dozen nodes or more.
  7.3.1 fixes it ([its notes](7.3.1.md)).
