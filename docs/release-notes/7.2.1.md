# Aleph-w 7.2.1 release notes

Language: English | [Español](7.2.1.es.md)

Aleph-w 7.2.1 is a patch release of graph algorithms. Prim's algorithm
could build a tree that was not minimal for a distance with state, could
not paint its tree, mapped the tree it built back to freed memory, and
leaked memory when a node of the tree could not be created.
Floyd-Warshall took the first of the parallel arcs between two nodes
instead of the lightest, ignored negative loops, could not rebuild some
paths in graphs that are not directed, and missed a negative cycle whose
cost is below the range of its distance type. And the binary heap ended
the program when its comparison threw.

It is source compatible with 7.2.0; a few calls that went wrong now throw
([Upgrade notes](#upgrade-notes)). As with every release, recompile
everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.2.1.
2. `Floyd_All_Shortest_Paths::get_min_path()` throws `std::domain_error`
   when the graph has a negative cycle; rebuilding the path could loop
   forever.
3. With an integer distance type, the constructor of
   `Floyd_All_Shortest_Paths` throws `std::overflow_error` when the sum of
   two distances is below `lowest()`, since the shortest distances cannot
   be represented. It used to discard such a sum, and could then report
   that there was no negative cycle.
4. `Floyd_All_Shortest_Paths` keeps a copy of its arc filter instead of a
   reference to it.
5. `insert()`, `update()` and `getMin_ne()` of `BinHeap` are `noexcept`
   only if its comparison is. With a comparison that may throw, what it
   throws reaches the caller; it used to end the program.

## Fixes

### Prim's algorithm

- **Trees for a distance with state.** `ArcHeap` ordered its arcs with a
  default-constructed distance, not with the one it was given; only the
  choice between two arcs that reach the same node used the given one.
  Prim, which gives its heap the distance of the caller, could then return
  a tree that was not minimal for it. The heap now orders the arcs by the
  given distance, so Dijkstra and A* with `ArcHeap`, and Prim, also accept
  a distance without a default constructor. Dijkstra and A* give the same
  results as before.
- **Painting.** `prim(g)` and `prim(g, start)`, which paint the tree on the
  graph, did not compile. Once they did, a loop on the first node could be
  painted, or leave the cookie of that node pointing to a freed heap node.
- **Mapping.** The nodes of the tree that `prim(g, tree)` builds mapped
  back to freed memory; the nodes of the graph mapped to the tree
  correctly.
- **Exceptions.** A distance that threw while the heap compared arcs ended
  the program. And when a node of the tree could not be created, the data
  that Prim had given to the nodes before it leaked.

### Floyd-Warshall

- **Parallel arcs.** Between two nodes, the matrices took the first arc
  inserted, and `get_min_path()` the first one it found. Both now take the
  lightest arc that the filter shows.
- **Loops.** A negative loop did not show as a negative cycle.
- **Graphs that are not directed.** `get_min_path()` threw
  `std::invalid_argument` when the path went against the direction in
  which an arc had been inserted.
- **Filters.** `get_min_path()` could take an arc that the filter hides,
  and the solver kept a reference to a filter passed as a temporary, which
  was gone once the solver was built.
- **Negative cycles and the range of the type**, as the
  [Upgrade notes](#upgrade-notes) explain: rebuilding a path with a
  negative cycle could loop forever, and a cycle whose cost is below
  `lowest()` went unseen.

### Binary heap

- **Comparisons that throw.** `insert()`, `update()`, `getMin_ne()` and
  the sifts under them were `noexcept`, so a comparison that threw ended
  the program, and `remove_all_and_delete()`, which the destructors call,
  compared the keys of a heap of 3 nodes or fewer. Now what the comparison
  throws reaches the caller, with the heap still destructible, and
  emptying a heap compares nothing.

## Documentation

- The documentation of `Floyd_All_Shortest_Paths` says how it treats
  parallel arcs, loops and graphs that are not directed, and lists the new
  exceptions.
- `insert()`, `update()`, `getMin()` and `getMin_ne()` of `BinHeap` say
  what happens when the comparison throws.
- [`VERSIONING.md`](../../VERSIONING.md) lists 7.2.1.
