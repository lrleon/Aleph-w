# Aleph-w 7.6.0 release notes

Language: English | [Español](7.6.0.es.md)

Aleph-w 7.6.0 is a minor release that makes the flow algorithms work
with a floating flow and with arcs of infinite capacity. With data that
are not exact in binary, as capacities or costs in tenths, the network
simplex, Ford-Fulkerson, the successive shortest paths and the cycle
canceling of 7.5.0 could stop short of the optimum, leave nodes
unbalanced, or not end; they end at the optimum now, checked against
exact oracles, and integer flows run as they did. An arc of infinite
capacity, which the documentation gives to an arc without a bound, takes
flow in every maximum flow, and the minimum cost flows refuse an
infinite maximum flow. 7.6.0 also deprecates `float` as the type of a
flow and the lower bounds of `Network_Simplex`: they go in 8.0.0.

It is source compatible with 7.5.0, but for the changes listed in the
[Upgrade notes](#upgrade-notes). As with every release, recompile
everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.6.0.
2. A network whose flow is `float` warns when it is compiled
   ([Deprecated](#deprecated)). The warning comes from the headers, so
   that including them between pragmas that ignore
   `-Wdeprecated-declarations` silences it while the code moves to
   `double`; GCC and Clang take the same pragmas:

   ```cpp
   #pragma GCC diagnostic push
   #pragma GCC diagnostic ignored "-Wdeprecated-declarations"
   #include <tpl_net.H>
   #pragma GCC diagnostic pop
   ```

3. `Network_Simplex::set_lower_bound()` throws `std::domain_error` for a
   bound other than 0, which 7.5.0 stored and then ignored;
   `get_lower_bound()` returns 0, and `residual_lower()` the flow of the
   arc. The three are deprecated.
4. `Network_Simplex::run()` throws `std::domain_error` when the flow of
   the network is not feasible (not finite, beyond the capacity of an
   arc, or not kept by a node other than the source and the sink), and
   when the program is unbounded: a cycle of negative cost through arcs
   of infinite capacity. In that case it first returns the residues of
   its pivots, so that `check_network()` holds after the exception. Its
   diagnostic members, `force_partial_arcs_into_tree()`,
   `is_valid_basic_solution()`, `count_non_tree_partial_arcs()`,
   `verify_tree_reduced_costs()`, `verify_tree_integrity()` and
   `print_diagnostics()`, throw `std::domain_error` before `run()`, whose
   structures they read.
5. `max_flow_min_cost_by_cycle_canceling()` takes negative costs, and
   throws `std::domain_error` for a cycle of negative cost whose arcs
   have no capacity, which has no bound.
6. `successive_shortest_paths()` throws `std::domain_error` for a cycle
   of negative cost anywhere in the residual network; 7.5.0 refused only
   those that the source reached, and gave a flow that was not of
   minimum cost when another one was there. A network whose source is its
   sink ends.
7. The successive shortest paths, the network simplex and the cycle
   canceling throw `std::domain_error`, that the maximum flow is
   infinite, when a path of arcs of infinite capacity goes from the
   source to the sink: a flow of infinite value has no cost to minimize.
   `successive_shortest_paths()` keeps the flows of the network as they
   were then.
8. With a floating flow, Ford-Fulkerson takes the shortest augmenting
   paths, as Edmonds-Karp: the depth-first paths took and spread the
   residues of rounding, and did not end on networks of a few hundred
   nodes. The value of the maximum flow is the same, but the flows of
   the arcs may differ from those of 7.5.0. An integer flow takes the
   depth-first paths, as before.
9. With a floating flow, the flows of the arcs may differ from those of
   7.5.0 in the last digits: the maximum and minimum cost flows return at
   their end the residues of rounding that their paths, pushes and pivots
   leave on the nodes, and keep the rounding that a node holds within its
   tolerance.
10. `Net_Sup_Dem_Graph::is_feasible()` and `non_feasible_nodes()` take,
    with a floating flow, a supply or a demand as met when the flow of its
    arc is within 1e-9 of its capacity, where 7.5.0 compared them exactly
    and refused feasible instances; an infinite supply or demand is met
    only by an infinite flow. Integer flows compare exactly, as before.
11. Equal infinite flows balance in `check_node()`, `check_network()` and
    `flow_value()`, and an infinite flow and a finite one do not; 7.5.0
    took any imbalance of a node with an infinite flow.

## New

- **A tolerance for Bellman-Ford.** The distance class of
  `Bellman_Ford` may give `Distance_Type tolerance() const`, not
  negative: a relaxation must then improve a distance by more than it,
  so that the rounding of floating sums does not make a cycle of weight
  zero negative, as an arc and its residual, of opposite weights, in a
  residual network. Without it the code is the same as before; with an
  integer distance the comparison stays within the range of the type.
- **Every maximum flow takes arcs of infinite capacity.** An arc of
  capacity infinity takes flow as any other, and a path of such arcs from
  the source to the sink makes the maximum flow infinite, which every
  maximum flow returns ([Fixes](#fixes)).

## Deprecated

- `float` as the type of a flow. Its epsilon, 1.2e-7, is 2^29 times that
  of `double`, so that the tolerances of the floating flows, relative to
  the data and to the epsilon of the type, hide real improvements with
  ordinary data (an arc of cost 500 on a network of 100 nodes, against
  2e11 with `double`); the tolerance of `check_node()`, 1e-9, is below
  it; and its integers stay exact only up to 2^24. `Net_Arc` warns when
  it is instantiated with `float` ([Upgrade notes](#upgrade-notes)). Use
  `double` instead. It is rejected in 8.0.0, as the
  [deprecation procedure](../../VERSIONING.md#deprecation-procedure)
  provides.
- `Network_Simplex::set_lower_bound()`, `get_lower_bound()` and
  `residual_lower()`: `Network_Simplex` supports no lower bound but 0.
  Use the flow of the arc instead of `residual_lower()`. They go in
  8.0.0.

## Fixes

- **The network simplex did not reach the optimum of a floating flow.**
  A pivot left an arc an ulp beyond its capacity, and `run()` ended as if
  optimal; its tolerances were absolute, 2.2e-13; the pivots ended
  silently at their bounds; an unbounded program pushed infinite flows;
  and residues of rounding were left that `check_network()` took as
  unbalanced nodes. It reaches the optimum now, with tolerances relative
  to the data, and returns its residues at the end.
- **Ford-Fulkerson broke the balance of the nodes** with a floating flow,
  and did not end on networks of a few hundred nodes in tenths
  ([Upgrade notes](#upgrade-notes)).
- **The successive shortest paths** missed the negative cycles that the
  source does not reach, did not end when the source was the sink, and
  rounding made Dijkstra loop, or a second run throw. They fill the arcs
  of their paths exactly now.
- **The cycle canceling** did not take negative costs, did not end on
  cycles of cost zero that rounding made negative, and could not take
  back the flow of an arc of capacity infinity or `max()`.
- **The residues of rounding and their consumers.** The return of the
  residues at the end of the augmenting paths also took the rounding that
  a node keeps within its tolerance, which left the flow no longer
  maximal: `min_cut()` put the sink with the source, the successive
  shortest paths threw after the simplex or the canceling, and
  `is_feasible()` refused feasible instances. That rounding stays now;
  Dinic and the capacity scaling return their residues too.
- **The supplies and demands of a floating flow.** `is_feasible()` and
  `non_feasible_nodes()` compared exactly, and took some 490 of 1500
  feasible instances in tenths for not feasible
  ([Upgrade notes](#upgrade-notes)); none now, with any of the five
  maximum flows.
- **The maximum flows with infinite capacities.** The capacity scaling
  did not end with any arc of infinite capacity; Dinic did not end on a
  path of such arcs; and the FIFO, heap and random preflows and HLPP
  returned an infinite flow on networks whose maximum flow is finite, as
  4 for s -> a of infinity, a -> t of 2.5, s -> b of 1.5 and b -> t of
  infinity. With assertions, Ford-Fulkerson and Edmonds-Karp aborted on
  an infinite maximum flow. All of them return the finite maximum flow
  now, and an infinite one when a path of arcs of infinite capacity goes
  from the source to the sink.
- **The minimum cost flows with an infinite maximum flow.**
  `successive_shortest_paths()` did not end, and the cycle canceling
  returned an infinite cost, or aborted with assertions
  ([Upgrade notes](#upgrade-notes)).

## Known limits

- **A far magnitude hides the floating improvements.** The tolerances
  that make the floating flows end are relative to the largest finite
  capacity, flow and cost of the whole network. One arc of a far
  magnitude, even one without flow, as a large penalty cost or a large
  finite capacity, hides the improvements below them among the other
  arcs, without notice, where 7.5.0 got them right. Measured: the
  simplex loses the differences of cost 1 from a cost of 5e12; with 100
  nodes, the canceling misses the cycles of cost -1 from 2e11, and the
  successive shortest paths the cheaper paths from 5e11; a capacity of
  1e13 keeps an arc of capacity 1 from taking flow. A capacity of `max()`
  or infinity is left out of the tolerances. The `@warning` of
  `Network_Simplex`, `max_flow_min_cost_by_cycle_canceling()` and
  `successive_shortest_paths()` say how to keep out of it.
- **The successive shortest paths after the simplex or the canceling.**
  Started from their flow, they may take a residue of the pivots, of an
  ulp, for a cycle of negative cost and throw: 10 and 31 of 500 networks
  of 4 to 12 nodes. A redesign of the tolerances is left for later.
- **Sums beyond the largest double.** The preflows and HLPP give an
  infinite flow, or abort with assertions, when the flows into a node
  pass the largest `double`, as with two arcs of 1e308 from the source
  into a node; the augmenting paths, Dinic and the capacity scaling are
  right.

## Tests

- `net_float_flow_test` (new): a `float` flow still works while it is
  deprecated.
- `tpl_netcost_test`: the network simplex with floating flows (decimal,
  tiny and large data, the pivots within the capacities, the residues,
  unbounded programs and infinite flows) and with integer flows (the
  lower bounds, an infeasible flow, the diagnostics before `run()`); the
  cycle canceling with negative and decimal costs, unbounded programs,
  and the flows of arcs without capacity; and an infinite maximum flow,
  which the simplex and the canceling refuse.
- `tpl_mincost_test`: the successive shortest paths with decimal
  capacities and costs, a second run, a source that is the sink, a cycle
  of cost 1e-7, a negative cycle apart from the source, and an infinite
  maximum flow.
- `tpl_maxflow_test`: arcs of infinite capacity with the eight maximum
  flows, decimal capacities with Ford-Fulkerson on a network of mid
  size, the residues of larger arcs and those that a node keeps within
  its tolerance, the minimum cut of a floating flow, and that Dinic and
  HLPP keep the cookies of the nodes.
- `tpl_net_test`: equal and unequal infinite flows, and the augmenting
  paths with an infinite maximum flow; `net_sup_dem_test`: the
  feasibility of floating flows, also of an infinite supply.
- `test_bellman_ford`: integer, signed and unsigned tolerances, and a
  tolerant distance that takes no cycle within its tolerance;
  `bipartite_test`: the matching of a sparse random graph, as
  Hopcroft-Karp.
- The graph harness checks negative costs and tenths, and the floating
  maximum flows against the exact maximum in tenths.
- Every new case fails, aborts or does not end against the headers
  before its fix.

## Performance

Counted with cachegrind, with GCC 14 and Clang 18 at `-O2 -DNDEBUG`,
against 7.5.0; each figure is the change in the instructions, GCC 14 /
Clang 18:

| | integer flow | double flow |
|---|---|---|
| Ford-Fulkerson | 0.0 / 0.0 % | −90.0 / −89.9 % |
| Edmonds-Karp | 0.0 / 0.0 % | +0.3 / +0.3 % |
| Network simplex | −6.1 / +0.5 % | −81.2 / −80.3 % |
| Successive shortest paths | −4.9 / −5.8 % | +0.6 / −3.3 % |
| Cycle canceling | −16.0 / −13.2 % | −89.9 / −90.2 % |
| Dinic | 0.0 / 0.0 % | +7.8 / +5.0 % |
| Capacity scaling | 0.0 / 0.0 % | +1.4 / +0.7 % |
| Heap preflow | 0.0 / 0.0 % | −31.5 / −22.2 % |
| Bipartite matching (Ford-Fulkerson) | | −1.4 % (GCC 14) |
| Bellman-Ford (default distance) | −2.8 to −18.0 % | |

The table measures the floating flows of #173. With a double flow, the
data are in quarters, where 7.5.0 also ends; in tenths, the maximum
flow, the network simplex and the canceling of 7.5.0 did not end, and
are not comparable. The infinite capacities and the floating supplies of
#179 change those figures by at most 0.07 % with a double flow, and not
at all with an integer one, but for the heap preflow, which runs 7.4 %
fewer instructions with GCC 14, as it is inlined differently. With a
double flow, Ford-Fulkerson takes the shortest paths: on a network of
unit capacities it runs 3.8 times the instructions of 7.5.0.

## Documentation

- `Network_Simplex`, `max_flow_min_cost_by_cycle_canceling()` and
  `successive_shortest_paths()` warn that a far magnitude hides the
  floating improvements ([Known limits](#known-limits)), and
  `solve_transshipment()`, `solve_assignment()` and
  `solve_transportation()` point to them; Ford-Fulkerson warns that its
  depth-first paths may not end with a floating flow.
- The maximum flows document arcs of infinite capacity, and
  `Net_Sup_Dem_Graph` the tolerance of its feasibility.
- `tpl_net.H` documents that `float` is deprecated, and how to silence
  the warning; `Bellman_Ford.H`, the tolerance of the distance.
- [`VERSIONING.md`](../../VERSIONING.md) lists 7.6.0.
