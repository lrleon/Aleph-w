# Aleph-w 7.3.1 release notes

Language: English | [Español](7.3.1.es.md)

Aleph-w 7.3.1 is a patch release of Floyd-Warshall, which since 7.2.1
threw `std::overflow_error` instead of reporting a negative cycle in
graphs of a few dozen nodes.

It is source compatible with 7.3.0, with a change of behavior in
Floyd-Warshall ([Upgrade notes](#upgrade-notes)). As with every release,
recompile everything against the new headers
([`VERSIONING.md`](../../VERSIONING.md#abi-compatibility)).

## Upgrade notes

1. `find_package(Aleph 7 ...)` accepts 7.3.1.
2. `Floyd_All_Shortest_Paths` stops at the first negative cycle: then
   `has_negative_cycle()` is true, the matrices hold no distances and
   `get_min_path()` throws `std::domain_error`, as before. The constructor
   throws `std::overflow_error` only with a weight below
   `lowest() / (2 (n - 1))`, with `n` nodes.

## Behavior changes

- **Floyd-Warshall stops at the first negative cycle**, which it finds
  before the first `k`, for a negative loop, or at the end of the `k` in
  which a node reaches itself at a negative cost. The matrices then hold
  no distances; with a negative cycle there are none.

## Fixes

- **Floyd-Warshall and negative cycles.** With a negative cycle, the
  distances that go round it double at each `k`, whatever the cost of the
  cycle, and since 7.2.1 the solver threw `std::overflow_error` as soon
  as a sum went below `lowest()`: with a single arc of −1 and `int`
  weights, from a few dozen nodes, depending on the order of the nodes,
  which the solver takes from their addresses. It now reports the cycle.

## Documentation

- `Floyd_Warshall.H` says what the matrices hold with a negative cycle,
  and when the constructor throws `std::overflow_error`.
- [`VERSIONING.md`](../../VERSIONING.md) lists 7.3.1.
